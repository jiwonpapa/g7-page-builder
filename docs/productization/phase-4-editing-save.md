## 구현 범위

- 기존 v1 문서의 레이아웃 카테고리는 계속 숨깁니다. 사용자가 `구조 편집 사용`을 선택하고 전환 영향에 동의한 경우에만 canonical context를 v2로 바꾸고 Section·Columns·Stack을 노출합니다.
- 전환은 변경 전 context를 복제한 뒤 v2 문서 전체 검증이 성공해야 반영합니다. 취소·byte/node/slot 검증 실패는 원래 v1 context·문서·공개본을 바꾸지 않습니다.
- 전환 동의는 기존 `onDirty → onChange → 자동 저장` 경로로 들어갑니다. 별도 저장소·상태 관리·히스토리 엔진을 추가하지 않습니다.
- 기존 Puck 공개 dispatch의 `recordHistory: true`를 이동·반복 항목·요소 스타일·미디어/경로 변경에 유지합니다. 저장 성공 시 Puck 컴포넌트를 remount하거나 history를 강제로 비우지 않습니다.

## 재사용한 완료 기능

- 저장 요청은 canonical snapshot·lock version·edit version을 분리합니다. 저장 중 새 편집이 생기면 늦은 응답으로 덮지 않고 최신 문서를 dirty로 유지한 뒤 필요 시 이어 저장합니다.
- 충돌은 서버 초안 재로드를 명시적으로 선택하게 하고, 일반 실패는 현재 문서를 유지한 채 재시도합니다. 저장 중 캔버스 편집은 유지하며 발행·문서 전환만 저장 완료 경계를 통과합니다.
- 선택 글자와 요소 전체 스타일, 한글 조합 입력, 부모 선택, 이미지 교체·비우기·대체 텍스트·비율·fit·초점, 반복 항목 순서 변경은 기존 공통 필드·미디어 경로를 그대로 사용합니다.
- dirty journal, 자동 저장, visibility 저장, beforeunload와 앱 내부 이탈 확인을 유지합니다.

## 검증 경계

- 순수 adapter 시험은 v1→v2 성공과 과대 문서 실패의 원본 불변을 확인합니다.
- 편집 surface 시험은 동의 전 구조 편집 비노출, 취소 무변경, 동의 후 v2 canonical 변경을 확인합니다.
- 기존 저장 회귀는 저장 중 연속 편집, 늦은 응답, 충돌·실패, 재시도, journal 복구와 이탈 확인을 담당합니다.
- 기존 직접 편집 시험은 글자 범위/요소 도구 충돌, 항목 내용·미디어·스타일 결합 이동, 미디어 변경과 Puck history 기록을 담당합니다.

4-C는 새 history 엔진·이미지 편집 앱·임의 CSS/HTML/JS·자유 좌표·임의 breakpoint를 추가하지 않습니다. 사람 콘텐츠/권리/시각 승인과 운영 배포도 완료로 표시하지 않습니다.
