## 수정 결과

1. Hero 반응형 정렬·글자 비율의 적용 대상을 바깥 wrapper에서 실제 내용을 그리는 첫 자식 요소로 옮겼다. 공통 정렬이 기기별 정렬을 덮거나 글자 비율이 두 번 곱해지지 않는다. 동일 공통 wrapper를 사용하는 블록에도 같은 규칙이 적용된다.
2. 실제 발행 비교에서 제품형 Hero의 기본 left 정렬이 명시된 center를 덮는 것을 확인했다. 공개 CSS의 기존 명시 정렬 규칙을 레이아웃 기본값 뒤·기기별 override 앞에 배치하고 명시 left도 같은 순서로 처리한다. 선택값이 없는 레이아웃의 기본값은 유지한다.
3. 슬라이더 항목 요약은 inert template의 텍스트로 표시한다. HTML 태그·엔티티는 화면용 문장으로 읽으며 제목 원문은 저장·변환하지 않는다. 빈 서식만 남으면 기존 순번 제목으로 표시한다.

제품 수정은 4개 파일이다: `page-builder-editor-appearance.css`, `page-builder-public.css`, `catalogFields.tsx`, `previewContent.ts`. G7 코어·문서 스키마·컴파일러·이력 엔진·콘텐츠/킷은 변경하지 않았다.

## 변경 전 재현과 변경 후 비교

로컬 Chromium에서 소유한 합성 문서를 실제 편집했다. 운영 사용자 문서를 사용하지 않았다.

| 항목 | 변경 전 실측 | 변경 후 실측 |
|---|---|---|
| 태블릿 right / balanced | canvas center / 18px | canvas·preview·published 모두 right / 16px |
| 모바일 left / compact | canvas center / 16.875px | canvas·preview·published 모두 left / 15px |
| PC center / large, 제품형 Hero | canvas center, 공개 출력 left | canvas·preview·published 모두 center / 18px |
| 슬라이더 요약 | `<strong>혜택</strong> &amp; 안내` | `혜택 & 안내`, 원래 제목 서식 보존 |

1280·768·360px에서 검증했다. 글자 비율 실측은 **블록의 기준 font-size**다. 제목·본문 자체의 rem/clamp 또는 명시적 글자 크기를 전부 다시 설계하거나 일괄 배율로 바꾼 것이 아니다. 편집기 전체의 픽셀 단위 동등성이나 모든 설정 조합의 완성을 주장하지 않는다.

기기별 값은 우측 패널에서 조작했고 저장·재열기 뒤 서버 원본과 비교했다. 같은 원본을 컴파일한 미리보기와 실제 2단계 발행 완료 페이지를 비교했다. 슬라이더는 서버가 수락한 원본을 기준으로 요약 표시 전후 제목·목록이 보존됨을 확인했다.

변경 전 증거: `output/playwright/ux2-baseline`, `/tmp/g7pb-ux2-baseline.log`. 초기 합성 문서 type·Outline 선택자·발행 API 연결·빈 문자열의 서버 정규화 비교 오류는 시험 연결을 교정했다. 제품 버그인 정렬·배율·HTML 요약 실패와 구분한다.
