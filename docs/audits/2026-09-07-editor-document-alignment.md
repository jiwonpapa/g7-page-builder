## 보존·제외

- 기존 productization의 콘텐츠6차와 site의 풀 테마6차는 서로 다른 역사입니다. 두 기록을 합쳐 삭제하거나 새 완료로 바꾸지 않습니다.
- 과거 승인/실패·개수·SHA·출력/브라우저 기록은 보존합니다. 현재 자동 기술검증 정책과 당시 승인 기록을 구별하며, 새로운 사람 승인 절차나 반복 전체검사를 추가하지 않습니다.
- 기존 Page Kit의 HeroSplit 사용은 실제 원본과 일치하므로 이름을 Hero로 고쳐 쓰지 않습니다. 갤러리 신규 삽입 숨김과 기존 문서 호환은 다른 경계입니다.
- root `README.md`는 `readme-intro-jwsoft-20260902`가 소유하므로 수정하지 않았습니다. AGENTS와 productization README에서 새 계획에 진입합니다.
- `docs/architecture.md`, 과거 structure 감사, 개별 phase 실행 보고서는 관련 문구를 검색/대조했으며 이번 새 목표와 무관한 개편을 하지 않습니다. 현행 진척은 부모 안내 문서와 새 원장으로 지정했습니다.
- 제품 PHP/TypeScript/CSS·런타임 문서 schema·manifest·제품 버전·기존 배포 ZIP을 변경하지 않습니다. 패키지에도 복사되는 안내는 계획 문서를 패키지 내부 상대 링크처럼 취급하지 않고 소스 저장소 경로임을 표시합니다.

## 검사의 범위

`make editor-plan-check`는 ID/스키마/날짜/안전 경로, 문서 표시문·현행 링크, 선행 관계·순환, 차단 사유, 담당 task, 완료 commit 기록과 기준별 증거, 원장/상태판 일치를 검사합니다. 조회·검사는 파일/mtime/coordination 상태를 바꾸거나 제품 테스트를 실행하지 않습니다.

commit 기록은40자리 형식과 필수 존재를 검사합니다. Git 객체·조상 관계·원본 테스트 로그의 진실성을 자동 보증하지 않습니다. 완료 증거는 저장소의 실행 요약에 연결하고 실제 확인은 작업 담당자가 수행해야 합니다. 문서 의미의 모든 모순을 기계적으로 차단한다는 주장도 하지 않습니다.

새 원장·계획·상태판이 변경되거나 원장이 있는 상태에서 관련 입력이 변경되면 scoped planner의 전용 검사가 적용됩니다. 원장 삭제도 변경 경로로 잡아 실패합니다. 기존 CI도 같은 planner를 사용하므로 별도 CI 서비스나 새 서버를 만들지 않습니다.
