# 독립 PB 개선 4차 — ImageText와 빠른 Undo

상태: 제품 구현·관련 검증·차수 커밋·로컬 통합 완료. 푸시·운영 배포는 하지 않았다.

## 범위와 구현

ImageText `media.image-text-01`의 `extra`에 배지·목록·구분선을 각각 0~1개 허용한다. 기존 Hero 도구를 `ComponentComposition`으로 공유해 같은 캔버스/Outline에서 삽입·선택·내용 편집·순서 변경·삭제한다. 제목·설명·대표 이미지·좌우 배치·기존 primaryLink는 원래 필드에 남는다. actions 슬롯이나 자동 버튼 이전은 추가하지 않았다.

공유 layout-policy의 종류·개수·깊이 규칙을 TS/PHP가 함께 사용한다. v1을 열기만 해서는 전환하지 않으며 구조 편집을 사용한 v2에서만 내부 요소를 저장한다. codec은 자식 ID·순서·표시 권한·반응형·명시적 빈 슬롯을 보존한다. ImageText 컴파일러는 본문 뒤·기존 버튼 앞에 검증된 자식을 렌더한다. G7 코어·새 블록·콘텐츠 팩·CSS는 변경하지 않았다.

## 빠른 Undo 원인과 수정

설치된 `@puckeditor/core` **0.23.0**의 `createHistorySlice`는 `record`를 250ms debounce로 실행한다. `back/forward`는 이 대기 기록을 정리하지 않으므로, Undo 뒤 늦게 실행된 `record`가 바뀐 index에서 histories를 잘라 Redo를 없앤다. 단순히 기록을 동기화하면 dispatch의 이전 store snapshot이 새 history를 덮는 두 번째 경계도 있다.

`vite.puck-history.ts`는 두 지점만 보정한다. 기록 대상 명령의 이력을 즉시 남기고, dispatch가 최신 history를 유지하도록 한다. Puck의 기존 기록 구조·back/forward·단축키·툴바·선택 상태·비기록 명령 처리는 그대로 사용한다. 별도 Undo 저장소나 원본 복제 엔진을 만들지 않았다. 위젯에서 전달되는 편집 명령 하나가 Undo 한 단계이며, 타이핑 위젯 자체의 변경 묶음은 유지한다.

보정은 PB editor production build에만 연결된다. 설치 파일을 직접 고치지 않는다. ESM/CJS의 검토된 upstream SHA-256만 수락하며 다른 소스 또는 보정 누락은 빌드 오류다. G7 네이티브 이력과 SitePart 자체 이력에는 적용하지 않는다. Puck 업데이트 때 해당 지문의 변경 원인과 upstream 수정 여부를 검토해 보정을 수정하거나 제거해야 한다.

## 검증

- 설치된 vendor의 실제 history와 dispatch 함수를 실행한 테스트 4개: 기존 지연 기록의 Redo 유실 재현, 같은 이벤트 시점의 3연속 명령과 Undo/Redo, 비기록 선택 및 새 편집의 분기 폐기, 알 수 없는 소스 거부.
- Hero/ImageText 공용 TS 테스트 8개: 자식 메타데이터 보존·구버전 호환·잘못된 슬롯/타입/개수 거부·이동/삭제/복제.
- PHP 대표 구성 테스트 3개: Hero 변형 유지, ImageText 좌우 출력·순서·버튼 보존 및 중복 구분선 거부.
- 실제 브라우저는 합성 소유 문서를 이용한다. 운영 사용자 문서를 조작하지 않는다. 3차 Hero 시험의 300ms 우회 대기는 제거했다.
- 변경한 빌드 제어부는 정확한 단위/브라우저 소비자를 필수로 등록했다. 테스트 수집 성공을 실제 제품 검증으로 세지 않으며 FULL이나 콘텐츠 전수 검증으로 확대하지 않는다.

## 실제 동작 증거

- Inspector 시나리오 2개 통과: 변경 이벤트부터 Undo 클릭까지 **250ms 미만** 확인, 2연속 Undo/Redo, Ctrl+Z/Ctrl+Shift+Z, 새 편집 후 redo 폐기 및 저장/재열기. 기존 300ms 대기 없음.
- Hero/ImageText 구성 시나리오 각각 통과: 추가·중복 제한·문구 편집·순서·삭제 직후 Undo·저장/재열기·미리보기·실제 발행·서버 위조 개수 거부·태블릿 읽기 전용. ImageText 구분선도 추가/이동/재열기를 확인했다.
- 좁은 패널에서 구분선 추가 버튼이 줄바꿈되는 문제를 확인해 부가 기호를 없앴다. 실제 버튼 높이 44px 미만 검사를 유지했다.
- 초기 원본 비교는 서버 정규화 전 합성 값의 빈 문자열/null 차이로 실패했다. 서버가 수락하고 저장한 원본을 비교 기준으로 정정했으며, 정규화를 무시하는 비교나 제품 원본 변경은 하지 않았다.
- 기존 1차/3차 기록의 빠른 Undo 미해결 항목은 **UI4에서 해결**했다. 과거 감사 기록은 당시 증거로 보존한다.

## 남은 범위

이번 목표는 ImageText extra와 빠른 Undo 결함이다. Hero/ImageText actions, 단일 Card의 내부 구성, 편집기 전체 상용 품질을 완료로 세지 않는다. 다음 독립 PB 차수는 단일 Card 내부 구성의 원본·허용 슬롯을 고정하고 구현하는 범위로 제안한다. 네이티브 NE 차수와 독립 PB UI 차수는 별개다.

이번은 로컬 커밋·통합 마감이며 버전 변경·푸시·운영 배포는 별도다. 새로운 내부 슬롯 지원에는 UI3와 동일하게 새 minor 릴리스 경계가 적용된다.

## 마감 하네스 수정

최종 integration-verify에서 이번 HeroComposition → ComponentComposition 이름 변경의 경로 집계 불일치를 재현했다. 조정기는 `--no-renames`로 양쪽 경로를 계획에 넣지만 CLI의 changed_paths는 Git rename 탐지를 사용해 이전 경로를 빠뜨렸다. 따라서 `Saved plan scope/phase changed`로 종료되었으며 제품 검사 실패와는 다르다.

CLI 변경 경로 계산에도 같은 `--no-renames`를 적용했다. 원본/목적 경로를 모두 보존하며 범위 비교·지문 검사를 완화하지 않는다. 이름 변경은 Git이 확인한 현재 목적 파일에서 관련 소비자를 찾으며, 대응되는 rename이 없는 삭제는 기존 명시적 검사 요구를 유지한다. 실제 임시 Git 저장소의 rename으로 변경 전 실패를 재현하고, 변경 후 조정기/CLI/저장 계획 실행의 경로 일치를 검사한다. 제품 코드는 재수정하지 않았고 기존 성공 브라우저 결과는 동일 입력·runtime 조건에서 재사용한다. 변경 전 재현 로그: `/tmp/g7pb-ux4-rename-before.log`.
