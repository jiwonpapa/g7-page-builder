# 3차: 사이트 킷 초안 설치와 재편집

검증 대상은 로컬 `https://g7pb.test`, G7 7.0.9 / Page Builder 0.33.1의 Unreleased 개발 변경이다. 외부 배포나 완성 테마 상품 출시 판정이 아니다.

## 구현

독립 페이지 빌더 관리 화면의 `사이트 킷`에서 회사소개·서비스 소개·문의 안내와 헤더·푸터를 함께 준비한다. 구성 선택 → 설치 이름·주소 입력 → 구성 확인 → 새 초안 설치 → 각 페이지와 설치한 헤더·푸터 세트 편집 순서다. 설치 결과는 같은 탭의 새로고침과 재진입에서 복원된다.

- 기존 Page Kit 한 페이지 구조를 변경하지 않고 별도 `g7pb-site-kit/v1` 계약을 추가했다. 원본은 기존 PageBuilderDocument와 SitePartDocument이며 HTML·JSON UI·Puck 상태를 설치 원본으로 사용하지 않는다.
- 미디어 경로와 SHA-256을 확인하고 모듈 미디어로 가져온다. 페이지·메뉴의 `g7pb-page://<key>` 연결을 사용자가 정한 주소로 해석한다.
- 누락된 구성, 중복 주소, 예약 주소, G7 경로 충돌, 컴파일 실패와 버전 호환을 확인한다. 사전 확인 후 주소가 바뀌는 경쟁은 실제 설치의 재검사와 DB unique 제약으로 차단한다.
- 모든 페이지·리비전·예약 주소·비활성 헤더·푸터 세트와 설치 영수증을 하나의 모듈 DB 트랜잭션으로 만든다. 실패한 문서 쓰기는 savepoint로 먼저 되돌린 뒤 해당 요청의 미디어를 정리한다. DB와 파일시스템 사이의 분산 트랜잭션을 보장한다는 뜻은 아니다.
- UUID 설치 요청과 요청 내용·작업자를 확인해 같은 요청을 중복 생성하지 않는다. 통신 오류 후에는 같은 요청을 보존해 결과를 다시 확인한다.
- 설치는 발행·활성 선택을 바꾸지 않는다. 페이지별 발행 후 추가 주소가 연결되며, 헤더·푸터는 세트 발행 후 명시적으로 적용한다. 이후 사용자가 주소를 변경할 때 기존 메뉴 링크까지 자동 추적하는 기능은 이번 범위가 아니다.

## 기존 산출물 복구

기존 `SitePartArtifactUpgrade` 준비 기능으로 누락된 과거 발행 산출물 6개를 생성했고 남은 누락은 0개다. 문서·리비전·발행본·Site Part 원본·활성 선택을 포함한 6개 테이블의 전체 행 해시가 준비 전후 일치했다. 재발행이나 원본 JSON 수정으로 대체하지 않았다.

근거: `output/playwright/site-phase3-20260906/artifact-preparation.json`.

## 검증

- 사이트 킷 계약 단위 시험: 3개, 9 assertions. 샘플 구성, 내부 주소·미디어 해석, 누락 참조·중복 주소·미지원 스키마 거부.
- 실제 저장 계층 통합 시험: 5개, 33 assertions. 읽기 전용 사전 검사, 비활성 초안 생성, 같은 요청 재시도, 작업자/내용 변경 거부, 설치 후반 실패의 전체 원복과 재시도, 사전 검사 이후 충돌.
- 설치 화면 단위 시험: 7개. 구성 확인 후 설치, 정확한 세트 편집 링크, 통신 실패·재진입에서 요청 ID 보존, 주소 변경 시 재확인, 충돌 차단, 늦은 응답 격리, 응답 검증과 공통 인증 전송, 다른 언어에서의 빈 목록 안내.
- 기존 공식 Page Kit 적용 브라우저 1개 통과. UI 통합에서 관리 화면 계약 2개, 페이지 생성·편집·발행·복원·재발행·발행 해제 1개, 헤더·푸터 편집 5개도 통과했다. 관련 PHP 회귀·타입·구조 검사와 production asset 검증을 통과했다.
- 새 사이트 킷 실제 브라우저 시나리오가 desktop/tablet/mobile 3개 프로젝트에서 모두 통과했다. 편집 화면은 PC 크기로 고정하고 각 실행에서 공개 페이지 3개를 1440·768·390px로 확인했다. 관리자 모바일 편집 지원을 검증했다는 의미는 아니다.
- 실제 구성 확인과 예약 주소 거부 → 설치 → 발행 전 404·기존 활성 세트 유지 → 설치 결과 재진입 → 페이지별 제목 수정·저장·재열기 → 미리보기 → 발행 → 설치한 헤더 수정·저장·재열기 → 세트 발행·적용 → 공개 메뉴 이동이 통과했다. 잘못된 발행 요청 후에도 마지막 정상 공개 결과가 유지됐다.
- 공개 화면의 제목·푸터·스크롤 모션 노출, 가로 넘침 없음, 브라우저 실행 오류 없음을 확인했다. PC·태블릿·모바일 결과 이미지를 직접 확인했고, 각 시나리오 종료 시 기존 활성 세트를 정상 API로 복원했다.

새 사이트 킷 통과 증거: `output/playwright/gates/site-phase3-integration-20260906/0ab19fc8167d0bdede47eb7311b28b589bc8b149af18660af12acef6af88470c/73231cd3293244a9812b699fb452c53e/`. 각 프로젝트의 `owned-installation.json`, 설치 전후 화면, 헤더 편집 화면과 공개 페이지 이미지를 보존한다.

UI 검증 전후의 문서·리비전·발행본·주소·Site Part 원본·Site Part 리비전·세트·발행 산출물 8개 테이블에서 기존 행의 누락·변경은 모두 0개다. 세트의 활성 선택(`is_active`)은 비교했으며, 정상 활성 복원 API가 기록하는 `updated_at`·`updated_by`만 비교에서 제외했다. 증거는 `output/playwright/site-phase3-20260906/source-preservation.json`이다. 구현 통합 SHA는 `b97fbcb104ffa78836816d972abe343c6ca2bc76`이다.

## 범위

샘플은 한국어 회사 사이트 안내 페이지 3개와 헤더·푸터 한 세트다. 브라우저 언어에 따라 G7 관리 화면의 문서 언어가 달라지므로 다른 언어에는 제공 킷이 없다는 안내를 표시한다. 문의 안내의 연락처·회사 정보는 운영자가 수정해야 하며 문의 폼 연동을 구현한 것으로 보지 않는다. 외부 사이트 킷 ZIP 가져오기·내보내기, 판매 결제, 기능 화면 편집, 전체 테마 호환성, 편집기 제품 완성은 이 차수의 구현·승인 범위에서 제외했다. 이 제외 목록은 현재 후속 실행 순서를 뜻하지 않으며, 현재 작업은 [편집 고도화 실행계획](../productization/editor-plan.md)을 따른다.

진단 과정에서 제목에 긴 공백 없는 시험 식별자를 붙이면 기존 Hero의 이미지 영역 아래로 글자가 침범하는 현상을 관찰했다. 이 차수의 화면 검증은 실제 한국어 안내 제목과 정상 스크롤 노출을 대상으로 하며, 임의 길이 영문·숫자 제목의 줄바꿈까지 보장하지 않는다. 검증용 새 문서·세트·미디어와 실패/성공 증거는 삭제하지 않고 보존한다.

최종 통합 검증에서 일반 `contenteditable` 선택자가 Puck의 임시 표시 영역을 잡아 제목 수정이 소실되는 시험 실패가 1회 재현됐다. 실제 ProseMirror 준비·포커스·전체 선택·키보드 입력을 확인하고, 서버의 문서 저장 성공 응답을 받은 뒤 재열기를 검사하도록 시나리오를 보완했다. 이어 iPad/iPhone 에뮬레이션을 물려받은 편집 문맥에서 전체 선택이 적용되지 않는 실패를 확인했다. PC 전용 편집은 화면 크기뿐 아니라 Desktop Chrome 기기 설정까지 고정했으며, 공개 페이지는 별도 방문자에서 1440·768·390px를 모두 검증한다. 모바일 기기의 편집 지원이나 Safari 호환성 승인으로 해석하지 않는다. 재실행 결과는 coordination의 최종 verification 기록을 기준으로 판정한다.
