# IP7 공개 CSS 용량 초과 진단

IP7 공통영역 계약의 통합은 공개 CSS 용량 검사에서 실패했다. Site Part 계약을 제외한 깨끗한 기준 `8c2685fd57c5c9aa3f4b38219f5a8987cbabf62c`에서도 같은 실패를 재현했다. 이후 2026-10-13 사용자가 공개 CSS 용량 상한 제거를 승인했다. 아래의 실패·최적화 비교는 변경 전 기록이며, 상한 제거는 IP7 완료 또는 브라우저 수용 증거가 아니다.

## 기준 코드 재현

Local 통합 task `integration-ip7-20261012`의 runtime lease를 확인한 뒤 Node 24.19.0에서 다음 명령을 실행했다.

```sh
./node_modules/.bin/vite build --config vite.effects.config.ts
node scripts/check-frontend-budgets.mjs
```

빌드는 성공했지만 검사는 `Frontend budget exceeded: dist/css/page-builder-public.css=20614/18700 gzip bytes`로 실패했다. 기존 Docker 통합 실행의 20,600바이트와 로컬 측정 20,614바이트는 환경별 결과이므로 같은 수치로 합치지 않는다. 둘 다 18,700바이트 기준을 넘는다.

현재 번들은 기존 블록·공통 셸 스타일과 v3 반응형 스타일을 포함한다. 메모리상의 AST에서 v3 전송 규칙만 제외해 원인을 분리한 수치는 18,452바이트였다. 이 제외본은 진단에만 사용했으며 제품 파일에 쓰거나 정상 빌드로 채택하지 않았다. 공개된 v3 HTML은 해당 스타일을 요구하므로 삭제해서 통과시킬 수 없다.

## 제한된 최적화 비교

동일한 로컬 빌드 출력에 대해 제품 파일을 덮어쓰지 않고 비교했다. 모든 크기는 Node의 기본 `gzipSync` 결과다.

| 비교 | gzip 바이트 | 판정 |
|---|---:|---|
| 현재 Vite 출력 | 20,614 | 기준 초과 |
| 연속된 동일 선언 규칙 병합 | 20,606 | 효과 부족 |
| v3 선언의 공통 선택자 묶음 | 19,941 | 기준 초과, 동작 미검증 |
| Lightning CSS CLI 1.33.0 재압축 | 20,534 | 효과 부족 |
| CSSO CLI 4.0.2 구조 최적화 | 20,031 | 기준 초과, 동작 미검증 |

두 CLI는 버전을 고정한 임시 진단 실행으로만 사용했다. 프로젝트의 package.json·lockfile·의존성 버전은 변경하지 않았다. [Lightning CSS](https://lightningcss.dev/docs.html)의 minify와 [CSSO](https://github.com/css/csso)의 구조 최적화 옵션을 조사했으나, 크기 감소가 충분하지 않아 제품에 추가하지 않았다. 압축 결과의 동작 동등성은 크기 측정만으로 인정하지 않는다.

## 승인된 정책과 검증 범위

비교한 방법은 기존 18,700바이트 기준을 충족하지 못했다. 이것이 추가 최적화의 불가능성을 증명하는 것은 아니다. 21,000바이트로 조정할지 확인한 뒤 사용자는 “css 한도 더더 높여 한도두지마”라고 지시했다. 이에 공개 CSS의 원본 105,000바이트와 gzip 18,700바이트 상한을 제거한다. 21,000바이트 등의 새 상한으로 바꾸지 않는다.

대상은 `resources/css/page-builder-public.css`와 `dist/css/page-builder-public.css` 두 용량 항목이다. 파일 존재 확인과 raw/gzip 측정값 보고는 유지한다. 다른 JS/CSS의 개별·합산 예산, 스타일 구조·문법·asset manifest·동작·시각 회귀 및 성능 검사는 유지한다. 제품 CSS·빌드 방식·의존성·문서 원본·공개 출력은 변경하지 않는다.

공식 task `ip7-public-css-unlimited-20261013`은 검사기·관련 하네스 시험·이 기록·CHANGELOG 네 파일만 소유한다. 하네스는 기존 두 상한과 21,000바이트보다 큰 공개 CSS가 측정·허용되는지, 두 파일 누락은 계속 실패하는지, 다른 CSS/JS 및 합산 제한은 유지되는지 확인한다. 검사기 검증과 Site Part 계약의 실제 제품 회귀 통합은 별개다. IP7은 계속 진행 중이며 G7 코어·테마 파일·운영 서버·사용자 문서는 변경하지 않는다.

## 적용과 검증 결과

정책 변경은 `459f4f83b8453ba8b69791c5745da7afd29d8602`로 제출하고 `9187a2c807c2f0493666c3cd7cfb313e54262dc0`으로 통합했다. 관련 예산 하네스 15개가 통과했다. 큰 공개 CSS 허용·측정, 원본/배포 파일 누락 거부, 다른 자산 상한 유지가 포함된다. 검사 계획 하네스 82개와 문법·계획 검사도 통과했다.

실제 예산 검사에서 공개 CSS는 원본 94,382바이트, 로컬 gzip 20,614바이트로 보고되고 통과했다. 후속 Site Part 계약의 FULL 통합에서도 Docker gzip 20,600바이트를 상한 없이 보고했다. 환경별 측정값은 구별하며 다른 자산 예산은 계속 검사했다.

막혔던 계약은 `c4e31a6008fcafb5a7563af68655d9b0f5fa5d8b`로 통합됐다. 제품 브라우저 49개와 공통 셸 45개를 포함한 FULL 회귀 결과·테마 복구·미구현 범위는 [Site Part 계약 검증 기록](2026-10-13-ip7-site-part-elements.md)에 남겼다. 이 결과는 공개 CSS 정책 적용과 기존 제품 회귀 증거이며, 새 Site Part 편집 UI 또는 IP7 전체 완료를 뜻하지 않는다.
