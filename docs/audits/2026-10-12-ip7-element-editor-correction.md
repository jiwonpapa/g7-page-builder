# IP7 공통 요소 편집 구조 교정

교정 설계 기준 SHA는 `6533e1e38482ab328f4a76130680e0c46689190b`다. IP7은 미완료다. 기존 243개 브라우저 시험 통과는 해당 구성의 동작 증거이며, 신규 구성을 코드 변경 없이 편집하는 구조의 완료 증거가 아니다. 아래 교정 전 판정과 이후 구현·검증 기록을 구분한다.

## 교정 전 코드 판정

| 대상 | 확인한 사실 | 처리 |
|---|---|---|

| 중단된 JSON 가져오기 UI 작업 | 블록별 의존을 그대로 둔 채 추가 입력 경로만 만듦 | 제품에 제출·통합하지 않음. 원본 변경을 보존하고 공식 lease 절차로 철회 |

공통 기본 요소의 렌더러 분기는 블록별 편집기가 아니다. 그러나 Hero·가격표·회사소개·문의 등 구성 이름에 따라 편집기·Inspector·삽입·렌더 함수를 새로 등록하는 구조는 허용하지 않는다. 기존 블록을 불투명한 `legacy.block` 요소로 감싸서 내부 편집을 완료 처리하지 않는다.

## 확정할 구현 구조

1. 모든 편집 원본은 기존 v3 공통 요소 트리다. 블록은 이 트리의 묶음이며 별도 편집 단위나 필수 분기 키가 아니다. 빈 페이지에서도 동일 요소·레이어·Inspector·핸들·단일 이력을 사용한다.
2. 구성 카탈로그는 검증된 JSON 정의와 이름·분류 등의 메타데이터만 제공한다. 정의에는 함수·벤더 상태·raw HTML/CSS/JS를 넣지 않는다. 내장 구성과 사용자 구성은 같은 검증·삽입 경로를 사용한다.
3. 일반 편집기는 카탈로그의 구체적인 이름이나 개수를 모른다. 기본 내장 카탈로그를 연결하는 조립 entry와 편집 커널을 분리한다. 새 구성 추가는 데이터 추가로 끝나야 하며, 소스 코드의 switch·등록 함수·조건문을 추가하지 않는다.
4. 삽입은 기존 `paste` 문서 명령 하나로 처리한다. 새 ID, 내부 링크 재연결, 참조 자산 가져오기, 다른 토큰 환경의 색상 보존, 단일 Undo를 그대로 사용한다. 현재 페이지 ID·slug·shell 및 기존 내용은 덮어쓰지 않는다.
5. 기존 63개 삽입 구성은 명시적으로 v3 데이터 정의로 옮겨 동작을 보존한다. 이 작업은 내장 라이브러리의 일회성 이행이며, 사용자 v1/v2 문서나 Site Part의 자동 전환이 아니다. 변환 도구가 실행 중 편집기의 필수 의존성이 되어서는 안 된다.
6. 새 기능은 이미지·아이콘·미디어·보호된 실행 영역 등 공통 요소/기능 계약으로 구현한다. 인증·게시판·결제·폼 실행은 포트/런타임 어댑터에 남기고 문서가 endpoint·handler를 소유하지 않는다. 미지원 기능을 정적 모양만 남기거나 감추어 완료 처리하지 않는다.

## 작업 순서와 소유 범위

각 작업은 clean base에서 정확 파일 PATHS를 claim한다. 다음은 작업 역할이며 디렉터리 전체 소유 선언이 아니다.

1. 이 교정 기록·현재 증거·IP7/IP10 수용 기준을 통합한다. 완료 상태는 올리지 않는다.
2. 중단한 가져오기 UI의 원본 branch·dirty 상태를 공식 active replacement로 보존한다. 대체 작업에서 잘못된 추가분만 철회하고 clean lease를 종료한다. 다른 작업의 변경은 건드리지 않는다.
3. 데이터 카탈로그 계약·검증·일반 삽입 모델을 별도 task로 구현한다. 공유 계약은 독점 lease를 사용한다. 선행 제출된 전화/이메일 링크 계약은 공통 링크 기능으로만 검토하며 연락처 전용 편집기 등록과 묶지 않는다.
4. 내장 구성의 데이터 정의와 명시 이행 도구를 별도 task로 분리한다. 기존 조립 함수의 런타임 import를 제거하고 테스트에서 이를 정적으로 차단한다.
5. 구성 패널·독립 mount를 일반 카탈로그 입력으로 연결한다. 이름별 세 삽입 경로를 제거한다. 데이터 정의·UI·공통 계약의 기능 의존 제출분은 공식 batch로 통합한다.
6. 새 이름과 처음 보는 배치의 구성을 고정된 같은 편집기 번들에 주입하여 브라우저 검증한다. 이후 같은 경로로 남은 내장 대상·공통영역·IP8~IP10을 완성한다. 대표 신규 구성 하나의 성공을 전체 수용으로 바꾸지 않는다.

현재 미통합 연락처·서식 본문 조립 함수는 보존한다. 이를 일반 편집기에 추가 등록하지 않으며 필요하면 명시 이행 도구에서만 재사용한다.

## 수용 검사와 실제 UX 감사

- **구조:** 실제 빌드 입력에서 일반 편집기 → 내장 manifest/블록별 factory 의존이 없어야 한다. 기능을 숨기거나 기존 시험을 삭제해서 통과시키지 않는다.
- **신규 구성:** 제품 번들 빌드 후 테스트 데이터로 새로운 이름·중첩·반응형 배치를 만든다. 새 코드/registry 분기/재빌드 없이 삽입·내부 선택·내용/스타일 편집·구조 이동·복제·Undo/Redo·저장/재열기가 동작해야 한다.
- **원자성:** 잘못된 schema·알 수 없는 실행 필드·누락 자산·초과 깊이/노드·잠긴 대상은 원본과 이력을 변경하지 않고 거부한다. 이름 변경은 편집 기능을 바꾸지 않는다.
- **출력:** PC·태블릿·모바일의 캔버스/preview/PHP 출력을 같은 준비 조건으로 비교한다. IP9에서는 실제 서버 저장·발행까지 같은 검사를 연결한다. 치수 기준 1 CSS px와 기존 품질 기준은 유지한다.
- **UX:** 사용자 화면에서 삽입 발견성, 내부 요소 선택, 직접 입력과 구조 선택의 전환, Inspector 적용 대상, 키보드/IME, 초점 유지, 오류 안내, 미저장/충돌/복구 흐름을 실제 조작한다. 텍스트는 포함 여부뿐 아니라 의도한 최종 값과 일치하는지 확인한다. 세 폭의 화면 캡처에서 가독성·넘침·가림도 확인한다.
- **완료 보고:** IP1~IP10 원장과 SPEC-01~16을 대조하여 구현·E2E·UX 감사·미달/수정/재검증·배포 여부를 구분한다. 테스트 개수나 구성 수를 제품 완성률로 대신하지 않는다.
