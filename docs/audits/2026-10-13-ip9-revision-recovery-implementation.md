# IP9 정밀 문서 리비전 복원 구현 인계

기준 SHA: f8250116b088ea5e2bbdb9edd5b9316f371574d0. task: editor-revision-recovery-20261013.

기존 모듈의 immutable revision 조회와 CAS 복원 API를 독립 포트 및 새 편집 화면에 연결한다. 저장한 v3 리비전만 복원하며 기존 v1/v2 문서를 전환하지 않는다. 후보의 전체 v3 원본·문서 ID, 현재 문맥·미저장 여부를 확인한 뒤 명시 선택으로 새 서버 초안을 만든다. 복원 응답의 새 lock, 원본 일치, 마지막 발행 hash 보존을 검증한다.

복원 진행 동안 편집 입력을 잠그고 성공 시 복원된 초안을 새 편집 세션으로 연다. 정상 저장은 기존 Puck 이력을 유지하며 host가 최신 CAS token을 별도 ref로 보존한다. 늦은 복원은 서버에 반영됐을 수 있으므로 취소·원복됐다고 주장하거나 다른 세션을 덮지 않는다. 충돌·응답 실패는 자동 재시도하지 않는다.

기존 repository는 publication.slug로 공개 페이지를 조회하고 revision 복원은 새 draft revision을 추가한다. 공개 포인터는 자동 교체하지 않는다. 공개 commit은 lock_version을 증가시키지 않으므로 확인한 기존 동작에 불필요한 token 변경을 추가하지 않는다. Site Part 리비전 복원은 별도 잔여 연결이며 이 증거를 대신하지 않는다.

문서함은 새 정밀 페이지 진입을 노출하고 v3 문서 편집을 해당 번들로 직접 연결한다. 기존 생성·편집 원본은 보존한다. 이 변경은 기존 문서 전환이 아니다.

## 별도 재감사 필요성

실제 저장→여러 편집→리비전 조회/명시 복원→재열기→발행, CAS 409 및 권한/readonly, 늦은 read/restore·문서 전환, 미저장 보호, 마지막 발행 경로/hash/본문 유지, metadata와 자산 및 복원 후 재저장을 확인한다. 3폭 복원/선택/포커스 UX와 새 정밀 진입 및 기존 문서함 회귀도 대상이다. 추가 시험 정의·E2E를 확대하지 않고 기존 선택 비런타임 검사만 수행한다.

실패 시 원인·대상·최초 결과와 최대 1회 재구현 결과를 보존하고 추가 반복하지 않는다. 구현·통합 SHA와 실행 기록은 공식 task metadata 및 최종 인계 보고서에 연결한다.
