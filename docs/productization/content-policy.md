# 블록 콘텐츠 제품 기준

상태: 1차 기준안 확정·개별 제품 승인 미실시. 적용: 2차 증거 계약, 6~7차 콘텐츠 개선, 8차 회귀.

## 공급 단위와 처리 상태

| 공급 분류 | 의미 | 새 기준에서의 취급 |
|---|---|---|
| 기본 요소 | 제목·본문·이미지·버튼·구분선 등 | 내용·크기·색·간격의 공통 편집 계약 |
| 레이아웃 틀 | Section·Columns·Stack | 빈 구조와 안전한 기본 배치, 3~4차 추가 |
| 완성 섹션 | 특정 목적의 문구·이미지·구조가 완결된 구역 | 선언·편집·시각 심사를 통과한 경우만 이 이름 사용 |
| 시작 페이지 | 목적과 다음 행동이 연결된 여러 섹션 | 5개 기존 Page Kit를 개별 심사 |
| 내 패턴 | 관리자가 저장한 Section 복사본 | 사용자 소유 데이터, 기본 제품 승인 수에 합산하지 않음 |

색만 다른 변형은 variant이며 별개 용도의 제품으로 과장하지 않습니다. 현재 manifest의 preset이 모두 ‘완성 섹션 합격품’이라는 뜻은 아닙니다. inventory의 `section-candidate`는 분류 후보입니다.

처리 상태는 유지/수정/통합/후보/호환입니다. 별도로 의미·권리·렌더·편집 심사 상태를 기록합니다. 이번 inventory의 `not-reviewed-under-v2`는 출시 차단 코드를 즉시 적용하거나 기존 승인을 삭제한 상태가 아니라, 새 기준 심사를 아직 하지 않았다는 뜻입니다.

## 심사 9조건

| 조건 | 합격 | 불합격 예시 |
|---|---|---|
| 목적 | 누구에게 무엇을 알려주고 다음에 무엇을 할지 명확 | 모든 업종에 같은 모호한 홍보 문구 |
| 내용 구조 | 제목·설명·근거·행동의 역할 구분 | 동일 의미를 여러 카드로 반복 |
| 카피 | 자연스러운 한국어, 실제 필드 길이에 맞는 문장 | ‘제목 입력’, 잘린 문장, 사실인 것처럼 보이는 예시 실적 |
| 시각 위계 | 제목·본문·버튼 구분, 의미 단위 줄바꿈·충분한 여백 | 제목 한 음절만 다음 줄에 고립, 내용보다 큰 장식 |
| 미디어 | 해당 내용과 연결, 교체 방법·권리·출처 추적 | 장식 사진만 반복, 내부 layout 이름을 alt로 노출 |
| 콘텐츠 변화 | 긴/짧은 문구·항목 최소/최대·허용된 비우기 유지 | 내용 증가 시 겹침, 첫 항목 편집 시 나머지 유실 |
| 반응형 | 1280/768/360 캔버스와 실제 공개 너비에서 읽힘 | 모바일 좌우 넘침, 버튼/표/긴 URL 접근 불가 |
| 편집 완결성 | 선언된 필드와 미디어·링크를 수정하고 저장/reload 가능 | 보기만 좋고 문구·이미지 일부가 수정 불가 |
| 접근성·표시 정확성 | heading·label·alt·키보드·대비, thumbnail/preview/public 의미 일치 | 키보드 접근 불가, 잘못된 CTA, 다른 레이아웃 썸네일 |

자동 검사는 DOM/계약/지표 근거이며 사람의 카피·시각 판단을 대체하지 않습니다. 문구/권리 변경 없는 CSS 수정은 의미 심사 재사용이 가능하지만 해당 렌더 증거는 갱신해야 합니다. 2차에서 영향 원장과 항목별 증거 버전을 구현합니다.

## 기본값과 데모

- 기본값은 허위 실적·별점·고객 증언·사업자 주소가 없어도 안전하게 저장/편집할 수 있어야 합니다.
- 완성 데모는 한 가지 명시적 예시 사업/서비스 문맥을 유지합니다. 데모 표시가 있다고 허구 후기를 무조건 승인하지 않고 해당 블록을 사용자가 교체/삭제할 수 있게 합니다.
- 필수 필드 누락은 설명 가능한 검증 오류로 처리합니다. 의미 없는 placeholder를 채워 발행 게이트를 우회하지 않습니다.
- 원격 랜덤 이미지·현재 날짜 의존 fixture는 사용하지 않습니다. 필수 alt/장식 alt는 각 schema 규칙에 맞춥니다.
- 최소 개수가 있는 배열은 그 개수만큼 의미 있는 기본 구조를 제공하고 명시적 빈 배열로 우회하지 않습니다.

## 6-A 대표 6개 — 정확한 개선 계약

| preset ID | 사용 목적과 필수 개선 | 대표 수정/검증 |
|---|---|---|
| hero.service-intro | 대상·제공 서비스·대표 행동을 첫 화면에 제시 | 긴 한국어 제목, 짧은 제목, CTA 경로, 대표 이미지 교체 |
| rich-text.article-intro | 독립적으로 읽을 수 있는 소개 본문 | 문장 일부 서식, 문단·목록·링크, 긴 본문과 읽기 폭 |
| image-text.company-story | 사진이 설명하는 회사/서비스 이야기 | 좌우 배치, 이미지 없음 허용 여부, 캡션/alt, 모바일 순서 |
| features.core-benefits | 서로 중복되지 않는 특징·혜택 | 항목 최소/최대, 순서·복제·삭제, 제목 길이와 높이 |
| card-grid.services | 비교하고 선택할 수 있는 서비스 목록 | 카드별 내용/링크·순서 보존, 긴 설명, 2/3열과 모바일 |
| cta.contact | 앞선 내용에서 문의/상담으로 자연스럽게 연결 | 문구·URL·보조 행동, 선택 범위/요소 스타일 분리 |

대표 6개만 바꿔서 기준 페이지 전체를 합격시키지 않습니다. inventory의 6-B block ID 목록은 실제 3개 문서에서 추출한 추가 검토 대상입니다.

## 6-B 기준 페이지 3개 — 완성 화면의 목표

### service-conversion

첫 화면에 구체적 제공 서비스와 상담 행동 → 핵심 혜택 → 진행 단계 → 검증 가능한 근거 또는 명확한 데모 근거 → 질문 → 상담 입력. 섹션마다 같은 상담 행동을 불필요하게 반복하지 않습니다. 현재 문의 폼 동작은 고정 Adapter/기존 폼 계약을 유지합니다.

시각 합격: 대표 제목·혜택 제목·질문 제목이 의미 단위로 읽히고 1~2글자만 마지막 줄에 고립하지 않는지 검토합니다. 긴 문구를 작은 글자로 무조건 축소하거나 잘라 숨기지 않습니다. 근거/후기는 본문보다 과장되지 않고 예시임이 분명해야 합니다.

### local-business

장소·실제 제공 서비스 → 방문 전 정보 → 예약/문의 절차 → 위치·운영 시간 → 연락/예약. 누구나 쓰는 ‘편안한 안내’만으로 업종 설명을 대신하지 않습니다. 주소·전화·지도·버튼의 관계를 확인합니다.

시각 합격: 사진이 장소 문맥을 전달하고 서비스 정보가 읽힙니다. 지도 실패/미설정 상태는 빈 회색 판으로 끝내지 않고 위치 텍스트와 대체 길찾기 경로를 제공합니다. 외부 지도 정상 로딩은 별도 실제 연동 검증으로 입증합니다.

### editorial-community

매체/커뮤니티 성격 → 대표 글 → 일정/자료 → 실제 탐색 경로. 글 카드의 사진·제목·설명이 같은 사건/주제를 설명해야 합니다. 뉴스레터 버튼은 지원되는 문의/신청 경로만 안내하고 없는 구독 시스템을 암시하지 않습니다.

시각 합격: 기사·일정·자료의 탐색 위계가 구분되고 모바일 날짜/버튼/제목이 서로 침범하지 않습니다. Page Kit의 편집 목록을 실시간 G7 게시판 데이터라고 표시하지 않습니다.

### 이번에 확인한 기존 화면 — 승인 아님

현재 Git에 포함된 3개 페이지의 desktop/mobile WEBP 6장을 직접 확인했습니다. 이는 당시 생성된 정적 산출물이며 현재 런타임을 조작한 증거가 아닙니다.

- 서비스 페이지에서 제목의 어절/음절 고립과 과대한 후기 표현을 새 기준의 검토 사례로 지정합니다.
- 지역 페이지의 지도 영역이 해당 정적 이미지에서는 비어 보입니다. 실제 지도 기능 장애로 단정하지 않고, 미설정/실패 상태의 대체 안내 검증 대상으로 지정합니다.
- 에디토리얼 페이지의 목록/자료 연결과 제목 줄바꿈을 검토합니다. 현재 탐색 링크 동작은 이 이미지로 판정하지 않습니다.
- 세 페이지 원본은 모두 호환 전용 `content.hero-split-01`을 사용합니다. 6차 새 배포 Kit는 현재 Hero 계열의 대응 layout으로 구성하되 기존 고객 문서/ID를 강제 변환하지 않습니다. 노출 정책과 Kit 생성 경로가 모순되지 않는지 검증합니다.

기존 화면: [서비스 PC](../../resources/store/dist/previews/service-conversion-desktop.webp), [지역 PC](../../resources/store/dist/previews/local-business-desktop.webp), [에디토리얼 PC](../../resources/store/dist/previews/editorial-community-desktop.webp). 당시 생성된 정적 화면이며 새 기준의 합격 화면이 아닙니다.

## 상태 fixture와 배치 운영

공통 상태는 default/long-copy/responsive/save-reload이며 배열 블록에는 collection-min-max, 미디어 조작 블록에는 media-missing, 데이터 블록에는 data-empty/data-error/capability-missing을 추가합니다. 비적용은 이유를 기록하고 공백으로 빠뜨리지 않습니다.

7차는 같은 계열끼리 최대 8개 프리셋의 하위 배치로 분할했습니다. 정확한 ID는 inventory가 정본입니다. 기존 시작 페이지 company-launch/event-launch는 7-F입니다. 이후 추가되는 layout 3종과 사용자 패턴은 현행 45/95/5 재고에 섞지 않습니다.

현재는 기준/사례를 정리한 상태이며 새 완성 화면을 생성하거나 형님의 시각 승인을 대신하지 않았습니다. 1차 종료 시 기준 검토, 6차에서는 새 대표 화면의 실제 합격 확인이 필요합니다.
