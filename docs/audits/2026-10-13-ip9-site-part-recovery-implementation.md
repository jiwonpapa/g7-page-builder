# IP9 정밀 Site Part 리비전 복원 구현 인계

사용자 지시: 기존 문서 전환 제외, 검증 확대 금지, 추가 제품 감사는 별도 보고로 인계, 재구현은 문제별 최대 한 번.

- 기존 read revision API와 CAS draft save API를 재사용합니다. 새 route/DB/원본 format을 만들지 않습니다.
- 선택 리비전의 Site Part v2 원본만 명시 확인 후 새 초안으로 복원합니다. v1은 비활성 표시하고 별도 문서 처리 프로세스로 남깁니다.
- 대상 kind/set/문서/locale/slug, 미저장 입력, 최신 CAS와 활성 발행 revision 보존을 검사합니다. 지연 응답은 바뀐 편집 문맥에 덮어쓰지 않습니다.
- 복원 대상의 세션만 명시적으로 다시 열며 다른 영역의 원본·미저장 입력·Undo는 유지합니다. 일반 저장과 Header/Footer 전환은 history를 재생성하지 않습니다.
- 실제 revision 조회·복원·CAS 충돌·마지막 발행 쌍·다른 영역 history의 UI 수용은 재감사 인계 대상입니다. 새로운 시험 정의·브라우저 실행은 추가하지 않습니다.

최초 구현. 실패 시 한 번만 보완하고 그 이상은 원인/영향/재감사 항목으로 동결 기록합니다.
