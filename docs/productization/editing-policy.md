## 이번 구현 종료·재감사 인계 규칙 (2026-10-14)

2026-10-13 사용자 직접 지시가 이번 실행 범위에 우선합니다. 기존 v1/v2 및 기존 Site Part의 전환·처리는 편집 기능 구현과 분리된 독립 프로세스로 남기며 이번에는 실행하지 않습니다. 아래 기존 이행 요구는 보존 요구이자 후속 문서 처리 계약이지 이번 구현 작업의 차단 선행조건이 아닙니다.

추가 E2E·시각/UI·UX·접근성·성능·전체 제품 재감사는 실행하지 않고 [실패·재감사 인계](../audits/2026-10-14-editor-implementation-handoff.md)로 대체합니다. 문제별 보완은 한 번만 허용하고 재발하면 실패 후보와 문맥을 보존하여 동결합니다. 한도를 소진한 실패를 다른 이름의 task로 재수정하지 않습니다. 성공한 동일 검사 입력은 재사용하며 새 제품 시나리오를 추가하지 않습니다.

`IMPLEMENTATION=1`은 runtime 검사와 그 종속 검사를 미실행으로 기록합니다. 타입/구조·선택된 기존 비런타임 검사와 공식 제출/통합은 유지하며 성공 receipt나 제품 수용을 위조하지 않습니다. 실패 보존·후속 프로세스 보존은 branch/SHA/worktree를 유지하며 제품에 통합하지 않습니다. CSS/JS 크기는 측정·경고이며 추가 구현을 중단하는 용량 상한으로 사용하지 않습니다.

원장 `done`은 기존 필수 수용 증거 확보 상태입니다. 이번 IP8/IP9의 소스 구현·통합과 IP7의 부분 통합·동적 기능 실패를 따로 표시하고 추가 감사가 없는 상태를 전체 제품 완료로 바꾸지 않습니다. G7 코어·기존 테마·운영 배포는 이번 작업에 포함하지 않습니다.

## 제품 목표와 독립성

피그마의 웹페이지 제작 경험을 목표로 한다. 페이지·Section·Container와 내부 텍스트·이미지·버튼 등을 캔버스와 레이어 트리에서 선택하고, 중첩·배치·크기·스타일·반응형 값을 수정한다. 블록의 문구와 몇 가지 프리셋만 바꾸는 수준을 완료로 인정하지 않는다.

- PageBuilderDocument가 단일 영속 원본이다. Puck Data/AppState, DOM, 생성 HTML과 G7 JSON UI는 원본이 아니다.
- PB가 문서·편집 명령·선택 의미·저장/발행 계약을 소유한다. Puck은 EditorAdapter 뒤의 교체 가능한 편집 엔진이며 이력 구현을 재사용한다.
- G7이 없어도 문서 검증·명령·편집 캔버스·직렬화·정적 결과 생성의 검증이 가능해야 한다. G7 인증·첨부·주소·데이터는 포트와 선택형 Adapter로 연결한다.
- 고객 서버의 기본 배포형은 계속 G7 모듈과 PHP·사전 빌드 JS/CSS다. 코어 독립은 완성된 별도 SaaS/범용 호스팅 제품이 이미 존재한다는 뜻이 아니다.
- G7 공개 모듈 API 의존까지 없어지는 것은 아니다. G7 업데이트 호환 시험과 마지막 정상 발행본 보호, 모듈 비활성화 시 route 소실에 대한 업데이트 중단 규칙을 유지한다.
- G7 코어 수정, private hook·registry·내부 import, G7 Layout Editor 또는 registerPanel의 필수 의존을 새 독립 편집기에 추가하지 않는다.

## 편집 대상과 보호 경계

| 대상 | 독립 편집기의 목표 |
|---|---|
| PB 소유 본문·Section·Container·기본 요소 | 구조·내용·배치·외형을 요소별 편집 |
| PB 소유 Header/Footer Site Part | 같은 기본 요소/스타일 원칙으로 상세 편집, 저장 revision은 문서별 유지 |
| Hero·Card·ImageText 등 내장 완성 블록 | 자식 요소로 편집 가능한 구성 템플릿으로 발전; 기존 원본은 명시적 이행 전 보존 |
| 반복 카드·슬라이더·데이터 위젯 | 반복 템플릿·데이터 연결·디자인을 구분; 반환된 서비스 데이터를 페이지 원본으로 덮지 않음 |
| G7 테마 Header/Footer·기존 G7 JSON·게시판/회원/결제 기능 | 자동 인수·변환하지 않음; 공개 capability로 연결하고 소유자·읽기 전용을 표시 |
| 외부 Code Pack·미지 블록 | 선언된 편집 capability만 지원; 원본 보존, 미지원 사유 표시 |

‘모두 세부 편집’은 PB가 소유한 페이지 디자인 요소 전체를 뜻한다. 인증·권한·결제·데이터 바인딩의 실행 코드를 임의로 고치는 기능은 아니다. 본문뿐 아니라 PB Header/Footer와 내장 카탈로그 전체를 목표에 포함하며 대표 Hero 하나의 성공을 전체 완료로 확대하지 않는다.

## 엔진과 추가 라이브러리

- React·TypeScript·Puck·Tiptap을 재사용한다. 기존 고정 Puck 0.23.0은 결합 검증의 출발점이지 새 목표를 만족한다는 증거가 아니다.
- Moveable은 정밀 리사이즈/스냅/허용된 그룹 조작, Selecto는 영역/다중 선택의 우선 도입 후보다. IP1에서 정확 버전·라이선스·React/iframe/좌표·입력 충돌·Undo를 검증한 뒤 의존성에 고정한다.
- 구조 삽입/재정렬은 Puck, 크기/좌표 핸들은 조작 Adapter가 담당한다. 한 포인터 동작에 두 엔진이 동시에 쓰지 않는다.
- 줌/팬은 기존 Puck 캔버스 경로를 먼저 사용한다. 부족함이 재현될 때만 Infinite Viewer 등 추가를 검토한다.
- Puck·Moveable·Selecto의 상태를 각자 문서/Undo로 저장하지 않는다. 단일 문서 명령과 한 이력 흐름으로 결합한다.
- GrapesJS로의 즉시 교체, 두 페이지 엔진 병행, 자체 DnD/리치텍스트/이력 엔진 복제는 이번 확정안에 포함하지 않는다. Puck 차단이 입증되면 요구를 줄이지 말고 근거와 대안을 보고한다.

## 정밀 편집과 저장 규칙

기능·값·상속·합격 기준은 [세부 스펙](independent-editor-spec.md)을 따른다.

- 크기·여백·정렬·타이포그래피·색상·테두리 등은 검증 가능한 typed 속성으로 표현한다. 유한 프리셋만으로 정밀 편집 요구를 대체하지 않는다.
- raw CSS 문자열·임의 class/Tailwind·HTML·JavaScript 입력을 원본 계약에 열지 않는다. 검증된 속성을 renderer가 CSS로 생성하는 것은 금지가 아니다.
- 일반 웹 배치는 Flex/Grid와 문서 흐름을 기본으로 한다. 겹침 요소는 명시적 부모 안에서 제한된 absolute 배치를 지원한다. 모든 요소를 transform 좌표로 바꾸지 않는다.
- 데스크톱 브라우저에서 PC·태블릿·모바일 폭 모두 편집 가능해야 한다. 기존 모바일 미리보기 전용 정책은 기존 모드의 현재 동작일 뿐 새 제품의 최종 정책이 아니다.
- 선택·줌·스크롤·hover는 Undo 문서 항목을 만들지 않는다. 한 드래그/다중 변경은 한 원자적 명령, Esc 취소·readonly·stale 응답은 무변경이다.
- 편집/미리보기/발행은 같은 레이아웃 의미·토큰·fixture를 소비한다. React 캔버스와 PHP compiler를 단순히 ‘같은 renderer’라고 부르지 않으며 치수·순서·줄바꿈을 실제 비교한다.

## 문서 호환과 보존 네이티브 모드

기존 v1/v2와 Site Part 원본·리비전·주소·발행본은 유지한다. 세부 디자인 문법은 새 버전 계약으로 구현하며 읽기만으로 자동 전환하지 않는다. 명시적 전환은 사전 검증·백업 revision·미지원 진단·Undo/복원·발행 전 확인을 요구한다. 상세 이행은 IP2/IP7/IP9에서 검증하며 이 정책 변경은 runtime schema 변경이 아니다.

기존 네이티브 확장은 유지보수/호환 트랙으로 보존한다. G7이 원본·선택·트리·Undo·저장을 소유한다는 경계와 원본 무손실·readonly·출처 보호는 계속 유효하다. 독립 PB의 선행조건이나 성장 기반으로 삼지 않는다. 기존 네이티브 코드를 제거하거나 자동 비활성화하지 않는다.

네이티브 NP01~NP10 및 H01~H08의 계약은 [보존 정책](editing-policy-native-20261012.md), 검증한 호스트 조합은 [호스트 계약](native-host-contract.md)에 남긴다. 미제공 API를 상상하거나 호스트 DOM/내부 상태로 우회하지 않는다. G7 측 수정은 별도 승인 대상이다.

## 진행과 완료 판정

- 새 실행 계획은 IP1~IP10이다. 기존 EP 및 NE/UI 완료 기록은 archive와 해시로 보존하고 새 목표의 완료 수에 합산하지 않는다.
- 정책·소스 구현·통합·실동작·배포를 구분한다. 이번 정책 단계는 제품 구현 항목의 분모에서 제외한다.
- 계획 시작 전 editor-status와 coord-status를 확인하고, 소유 파일 안에서 원장·표시판을 함께 갱신한다. 종료 전 editor-plan-check를 통과한다.
- 구조 검사만으로 편집 성공을 주장하지 않는다. 관련 단위/왕복/서버 검증과 실제 포인터·키보드·저장·재열기·출력 증거가 필요하다.
- 벡터 펜/불리언 그래픽·프로토타이핑·실시간 공동편집·판매용 테마 증설은 이번 편집기 목표 밖이다. 웹 정밀 편집의 미완료 기능을 이 제외 목록으로 숨기지 않는다.
- 운영 배포·G7 코어 변경·기존 데이터 파괴적 정리는 별도 승인 없이 진행하지 않는다.
