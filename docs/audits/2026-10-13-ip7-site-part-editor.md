# IP7 공통 요소 Site Part 편집 화면

IP7은 진행 중이다. 이 차수는 저장 계약이 통합된 `d9fdc96fa201afe2dca25e608ef6664333787eb5`에서 Header·Footer를 기존 공통 요소 편집기에 연결한다. 구성 이름별 Inspector·삽입·렌더 코드는 추가하지 않는다.

## 범위와 소유권

공식 task `ip7-site-part-editor-20261013`은 24개 이하의 정확 파일을 claim한다. 새 정밀 세트 명시 생성, 버전별 편집 화면 진입, 동일 StructureEditor의 두 독립 문서 세션, 각 문서의 저장과 쌍 발행·별도 활성화를 구현한다. 한 문서를 두 엔진에 중복 저장하지 않는다. 새 세트 생성은 기존 세트의 변환·자동 활성화가 아니다.

각 Header/Footer의 Puck 이력은 탭·미리보기 전환 동안 보존한다. 비활성 문서는 입력을 받지 않는다. 저장 중 입력·409 충돌·늦은 응답은 기존 문서 세션 규칙을 재사용한다. 저장·발행 후 CAS 번호만 갱신하며 문서나 이력을 다시 마운트하지 않는다. 발행은 두 저장 버전을 함께 보내고, 사이트 적용은 별도로 확인한다. 구형 편집기는 v2를 기존 codec으로 보내지 않고 정밀 화면으로 연결한다.

## 검증

공통 Site Part Blade entry가 저장 버전에 맞는 고정 번들을 선택하도록 바뀌므로 공유 화면 런타임 변경 사유로 제출·통합에 `FULL=1`을 명시한다. 기존 기준은 유지하며 추가 v3 시나리오를 기존 제품 시험으로 대체하지 않는다.

착수 후 새 API/저장 포트/화면 단위 시험 32개와 기존 페이지 호스트 14개, TypeScript strict 및 제품 소스 12파일 구조 검사가 통과했다. 이는 브라우저 검증 전 결과다.

검사 계획과 관련 Unit/E2E를 이 소스 범위에 등록한다. E2E는 빈 Header/Footer UI 생성, 내부 요소·한글 직접 입력·반응형 스타일·탭 전환 Undo/Redo, 저장·재열기, 쌍 발행, 별도 활성화와 세 폭의 편집/미리보기/PHP 공개 출력 1px 비교를 다룬다. 지연 저장과 실제 409 충돌도 별도 시나리오로 확인한다. 시험 전용 세트만 기존 소유 fixture에 예약·등록하며 종료 시 원래 활성 상태를 복구한다.

검증 결과와 제출·통합 SHA는 실행 후 기록한다. 시험 정의·수집이나 단위 통과만으로 브라우저 성공을 선언하지 않는다. 기존 원본의 명시 이행·복원, 고정 G7 실행 capability 연결 및 전체 카탈로그 수용은 이 차수 완료와 별개인 IP7 잔여 요구다. G7 코어·테마 파일·운영 서버는 변경하지 않는다.
