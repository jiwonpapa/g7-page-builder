# IP7 공개 문의 입력 수명

설치형 폼 시험에서 입력값 손실 1건을 확인하여 원인을 분리한다. 이 작업은 PB 소유 문의 폼만 대상으로 한다. 테마와 G7 코어는 읽기 전용이며 제품에서 내부 코드를 import하거나 고치지 않는다.

격리 재현은 React 호스트가 같은 컴파일 HTML을 다시 렌더하는 상황에서 기존 PB hydration과 문의 runtime을 그대로 실행한다. 네트워크·테마를 흉내 내는 제품 코드를 추가하는 것이 아니라, 기존 DOM 교체 시 입력 보존 여부를 확인하는 회귀 시험이다. 실제 설치형 원인은 별도 visitor trace와 수명 기록으로 확인해야 한다.

입력 보완이 필요한 경우 문서·주소·폼 구조가 같은 즉시 재렌더에서만 미전송 입력을 전달한다. 다른 문서/개정/폼, 명시적 reset, 늦은 재마운트 또는 전송 중 요청을 자동 재전송하지 않는다. 장기 저장소·다른 페이지·G7 전역에 입력을 보관하지 않는다. 구현 및 통합 성공은 실제 실행 뒤 기록한다.

## 격리 재현과 값 전달 부품

기준 `9b247a9734eb332ab0617e4dbc045ab51d1a8d50`에서 React의 같은 `dangerouslySetInnerHTML` 렌더를 반복하자 새 form으로 바뀌며 `Visitor input`이 빈 문자열이 되는 실패를 확인했다. 실제 테마 코드를 복사하거나 import하지 않았다.

`inquiryContinuity.ts`는 일반 입력/본문/체크 값의 순수 snapshot·동일 원본 확인·복원만 맡는다. 숨은 값·비밀번호·파일은 가져오지 않고, 주소·action·소유 ID·전체 원본 form이 달라지면 아무 것도 쓰지 않는다. 이벤트·전송·네트워크·장기 저장은 하지 않는다. 관련 9개 시험과 TypeScript strict가 통과했다. runtime의 정확한 교체 시점·전송 중 거부·폐기 연결은 다음 소유 task에서 수행해야 하며 이 부품만으로 실제 입력 손실 해결을 선언하지 않는다.
