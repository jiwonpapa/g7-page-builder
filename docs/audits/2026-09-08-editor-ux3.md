# 독립 PB 개선 3차 — Hero 내부 구성

상태: 구현·차수 커밋·로컬 통합·관련 실제 브라우저 검증 완료. 푸시·운영 배포는 하지 않았다.

## 변경 범위

`content.hero-centered-01`의 `extra` 슬롯에 기존 배지·목록을 각각 1개까지 배치한다. 같은 Puck 캔버스와 Outline의 실제 자식이며, 우측 `내부 구성`에서 삽입·선택·편집·순서 변경·삭제한다. 제목·본문·대표 이미지·기존 CTA 필드는 원래 소유권을 유지한다. 일반 블록 갤러리에서 삽입한 블록은 Hero 옆에 배치하며 암묵적으로 내부에 넣지 않는다.

- TypeScript와 PHP가 공유 JSON의 허용 슬롯·자식 종류·개수를 검사한다. 기존 최대 깊이·노드 수 제한은 유지한다.
- codec은 자식 ID·내용·반응형·표시 설정과 명시적 빈 슬롯을 보존한다. v1 문서를 열기만 해서는 v2로 바꾸지 않는다. 구조 편집을 사용하기 전에는 내부 삽입을 비활성화한다.
- 컴파일러는 검증된 자식 결과를 Hero의 본문 뒤·기존 CTA 앞에 배치한다. 임의 HTML 필드나 DOM 문자열 치환을 추가하지 않았다.
- 기존 Puck 명령·Undo를 사용한다. 태블릿/모바일 미리보기에는 내부 변경 도구를 비활성화한다.
- 신규 CSS·블록·페이지킷·G7 코어 변경은 없다.

## 검증 결과와 증거

새 실제 로컬 Chromium 시나리오가 통과했다. 소유한 합성 문서로 배지/목록 삽입, 중복 삽입 비활성화, 배지 문구 편집, 순서 변경, 삭제, Undo, 저장·재열기, 미리보기·실제 발행 출력과 원 CTA 보존을 확인했다. 서버에 허용 개수를 넘긴 원본을 직접 보내면 `400 / G7PB_DOCUMENT_INVALID / component_slot_limit`으로 거부되고 마지막 정상 원본이 유지된다. 태블릿 미리보기에서 내용이 유지되고 삭제 도구는 비활성화된다.

새 단위 검사는 TypeScript 4개, PHP 2개다. codec의 ID/메타데이터·이전 문서 호환, 삽입 위치·허용 개수, 순서/삭제/복제, 기본·제품형·균형형 Hero 컴파일 순서와 서버 정책 거부를 다룬다. 관련 기존 단위 검사, TypeScript strict, PHP 정적 검사, 구조 검사, production build 및 자산 검사도 함께 실행했다. 컴파일러 coverage는 facade 93.68%, family 89.44%로 기존 87% 하한을 통과했다.

## 관련 하네스 변경

정책 JSON 및 공용 fixture 변경에 대해 양 언어의 정확한 소비자 검사를 등록했다. 미등록 스키마의 전체 범위 요구와 알 수 없는 경로의 거부는 유지한다. 새 Hero 테스트도 해당 입력 변경 시 재사용하지 않도록 등록했다. 기존 갤러리 단위/lifecycle 검사의 Hero 미지원 기대값을 새 기능 범위에 맞췄다. 하네스만 바뀐 제출 단계의 테스트 수집 결과를 실제 브라우저 통과로 계산하지 않았다.

## 제한과 다음 범위

이번 완료는 Hero extra 배지·목록 각 1개에 한정한다. Hero actions·ImageText·Card 내부 구성과 임의 중첩 요소 편집의 완료를 뜻하지 않는다. 빠르게 연속 조작할 때의 기존 Puck Undo 이력 문제는 이전 차수의 미해결 사항으로 유지한다. 이번 브라우저 Undo는 삭제 후 이력 기록 간격을 두어 확인했다.

다음 독립 PB 개선 4차의 제안 범위는 ImageText 내부 구성이다. 실제 허용 슬롯·기존 필드 소유권을 먼저 고정한 후 같은 원본 보존·저장/재열기·출력 기준을 적용한다. 아직 착수하거나 완료 처리하지 않았다.

배포 시 새 슬롯을 지원하는 minor 릴리스가 필요하다. 이전 릴리스로 새 슬롯 문서를 편집/재컴파일하지 않는다. 이번 차수에서는 버전 변경·푸시·운영 배포를 하지 않는다.
