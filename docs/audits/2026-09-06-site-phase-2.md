# 2차: 일반 페이지 주소 할당과 편집 원본 보호

검증 환경: 로컬 `https://g7pb.test`, G7 7.0.9 / sirsoft-basic 1.1.1 / Page Builder 0.33.1 개발 변경. 외부 배포나 상품 출시 승인이 아니다.

## 결과

기존 페이지 생성·편집·미리보기·발행 흐름에 `/about`, `/company/about` 같은 추가 주소 설정을 연결했다. 독립 관리 화면에서 문서의 `주소·설정` → `주소 할당·메뉴 연결`을 열어 주소를 저장한다. 기존 `/pages/{slug}`는 그대로 유지한다.

- 초안 주소는 예약만 하고 정상 발행 후 공개된다. 초안 수정·실패한 발행은 마지막 정상 발행본을 바꾸지 않는다.
- 시스템 예약 경로, 기존 G7 정적/매개변수 경로, 다른 문서의 주소 및 오래된 저장 버전을 거부한다. G7이 나중에 같은 경로를 등록하면 G7 경로를 우선한다.
- 활성 사이트 템플릿 방식의 발행본만 추가 주소를 사용한다. 독립 Header/Footer 또는 공통영역 없는 출력은 이번 추가 주소 연결 대상이 아니다.
- 주소 변경·해제는 초안 저장과 별개이며, 이미 발행한 페이지에서는 즉시 적용된다. 화면에 이 동작을 안내한다.
- 주소 복사와 헤더·푸터 메뉴 편집 진입을 제공한다. G7 `/admin/menus`는 관리자 사이드바이므로 방문자 메뉴 연결 화면으로 쓰지 않는다.

## 편집 원본과 G7 연결

`with_source_meta`로 받은 네이티브 편집 원본은 런타임 Site Shell 장식을 건너뛴다. 공개 출력에만 헤더·푸터를 연결한다. 저장 후 문자열 삭제나 생성 JSON 직접 수정을 사용하지 않는다.

G7 공개 route merge filter로 기존 모듈 layout과 발행 슬러그를 연결한다. 실제 DI에서 선택 의존성의 기본 null 때문에 라우트 등록이 빠지던 문제도 수정했다. 모듈 소유 `g7pb_page_routes` 테이블만 추가했으며 G7 페이지·메뉴 테이블을 사용하지 않는다.

메뉴 발행 및 활성 세트 전환은 공개 layout 캐시를 갱신한다. 실패한 저장·발행에서는 캐시를 갱신하지 않는다.

## 검증

- `pageAddressFlow`: 화면에서 새 문서 생성, 블록 추가, 예약 주소 거부, 추가 주소 저장, 미리보기, 발행, 비로그인 공개 표시, 실패한 발행 요청 후 출력 유지, 설정 재진입.
- 공개 화면 1440 / 768 / 390 폭: 각 기기 폭으로 다시 접속해 본문과 가로 넘침을 확인. G7 JSON UI가 최초 접속 때 기기 구성을 해석하므로 데스크톱 로딩 뒤 창 크기만 바꾼 결과와 구분한다.
- `pageBuilderLifecycle`: 생성·발행·이전 리비전 복원·재발행·발행 해제 회귀 통과.
- `managerCodeContracts`: 서로 다른 관리 대화상자의 비동기 응답 소유권 검사 통과.
- 네이티브 편집기: 소유한 1차 회사소개 fixture만 원본으로 복구한 후 본문 직접 수정, 저장 HTTP 200, 재열기, 비로그인 공개 HTTP 200. 저장 원본의 런타임 주입 노드 0개. 원래 편집본은 증거로 보존했다.
- PHP 주소 충돌·발행 상태·독립 저장 버전·권한 검사, UI 응답 검증·실패 유지·늦은 응답 격리, TypeScript, PHPStan, Pint, 구조 검사 및 프로덕션 빌드 실행.

원시 증거는 `output/playwright/site-phase2-20260906/`, 하네스 검증은 `output/playwright/gates/site-phase2-integration-20260906/`에 보존한다.

## 메뉴 연결 실증과 보존

소유한 `2차 메뉴 연결 검증` 세트에서 메뉴 이름과 연결 주소를 UI로 수정하고 저장·세트 발행·활성화를 수행했다. 일반 Chrome 사용자 에이전트로 홈의 `2차 회사소개` 메뉴를 클릭하여 `/company/phase2-1788651089031`의 발행 본문까지 이동했다. `menu-proof.json`, `menu-public-navigation.png`에 결과를 보존했다. 이후 원래 활성 세트 선택으로 원복했다.

헤드리스 기본 사용자 에이전트는 현재 G7에서 검색 봇용 SSR로 처리된다. SSR에는 템플릿 기본 메뉴가 출력되므로 일반 브라우저 Site Shell 적용 결과와 구분했다. 실제 방문자 화면은 Desktop Chrome 사용자 에이전트와 별도 비로그인 컨텍스트로 확인했다.

G7 소스 3,478개 파일의 해시는 전후 동일했다. 기존 페이지 문서·리비전·발행본·Site Part 원본과 산출물의 기존 행 해시는 보존됐다. 테스트용 새 문서·세트·리비전과 네이티브 테스트 fixture의 저장 이력이 추가됐다. 기존 기본 세트 한 행은 테스트 선택 원복 후 활성 상태는 동일하며 활성 전환의 감사 시각/수정자 이력만 남는다. G7 기본 페이지 및 기존 템플릿 layout 행은 바꾸지 않았다.

증거 비교는 `preservation-diff.json`이다. 기본 키 없는 목록의 행 순서 차이는 변경으로 세지 않고 행 해시의 개수로 비교한다. 테스트 문서 및 증거는 검토용으로 보존했으며 임의 정리는 실행하지 않았다.

## 범위와 남은 차수

2차는 일반 페이지 운영 동선의 기반이다. 완성 테마 상품, 여러 페이지·메뉴의 일괄 설치, 기능 화면 편집, 전체 테마 호환성 또는 편집기 제품 완성 판정으로 확대하지 않는다. 3차는 검증된 페이지·헤더·푸터·주소·메뉴를 하나의 킷 구성으로 설치하고 재편집하는 흐름이 우선이다.

기존 기본 헤더·푸터 세트는 과거 발행 산출물이 준비되지 않아 정상 활성화 API가 409를 반환했다. 기존 세트를 재발행하지 않았으며 테스트가 바꾼 활성 선택만 원복했다. 기존 문서·발행본은 유지하고 활성 전환의 감사 시각은 변경 이력으로 남긴다. 이전에 오염된 고객 원본을 자동 복구하지 않는다.
