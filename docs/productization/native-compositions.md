# 네이티브 내 조합 — NE4 계약

수용 기준: `NAT-04`. 사용자별 재사용 스냅샷을 보관하고 G7의 허용된 위치에 독립 사본을 삽입한다. 페이지 원본·선택·Undo/Redo·저장·공개 출력은 G7이 소유한다. 운영 제공 여부는 [차수별 진척](editor-progress.md)과 별도 릴리스 기록을 따른다.

## 사용 흐름

1. 일반 페이지의 편집 가능한 항목을 선택하고 상세 편집 패널에서 **편집 도구 → 내 조합**을 선택한다.
2. 조합 이름을 입력하고 **선택 항목을 내 조합에 저장**한다. 선택한 노드와 지원되는 내부 구성만 보관하며 페이지 저장을 실행하지 않는다.
3. 현재 목록에서 이름으로 찾고 다른 허용 위치를 선택한 뒤 **조합 삽입 위치 → 삽입 순서 → 조합 삽입**을 사용한다.
4. 삽입은 G7의 기존 이력 한 건이다. Undo/Redo 후 기존 상단 **저장**을 사용하면 공개 페이지에 반영된다.
5. **목록에서 삭제 → 삭제 확인**은 개인 보관 항목만 제거한다. 이미 삽입한 페이지 사본과 G7 첨부 파일은 유지된다.

빈 목록, 요청 진행, 오류, 미지원 버전을 구분한다. 짧은 옵션은 기존 공통 라디오를 유지하고 가변 길이의 구조 경로만 위치 Select로 표시한다. 페이지/선택/revision이 바뀌면 진행 요청을 취소하고 입력·삽입 위치를 초기화한다. 조회한 목록은 유지한다. 열 때 목록을 자동 조회하고 새로고침과 30개 단위 페이지 이동을 제공한다. 검색은 현재 조회한 목록에만 적용된다. 상세 편집 / 삽입·구성 / 내 조합을 구분하며 G7의 기존 페이지 설정·미리보기·저장을 사용한다.

## 원본과 포맷

| 소유자 | 계약 | 의미 |
|---|---|---|
| PB | `g7-page-builder/native-composition/v1` | 사용자 id, UUID, 이름, 생성일과 불변 G7 스냅샷 문자열. 개인 API [계약](../api-native-compositions.md) |
| G7 호스트 | `g7.editor-composition/v1` | 선택 node, templateIdentifier, layoutName, renderer/spec/nesting signature, 사용 범위 |
| 기존 독립 PB | PageBuilderDocument / Section 패턴 | 다른 포맷. 네이티브 조합과 혼용·자동 변환하지 않음 |

페이지 전체를 두 번째 문서로 저장하거나 동기화하지 않는다. 여러 최상위 본문 항목을 자동 포장하지 않으며, 선택 가능한 본문 컨테이너의 지원 하위 구성을 저장한다. 판매 킷·파일 교환·공유 라이브러리·연결형 전역 컴포넌트 기능은 포함하지 않는다. 서버는 snapshot을 JSON 문자열 그대로 보존하여 빈 객체 `{}`와 배열 `[]`, 미지 필드를 구분한다.

## 호환과 무변경 거부

- 호환 G7 공개 `host.compositions.export/insert`가 필요하다. 문서/템플릿·노드 경로·세션·revision·readonly 문맥을 비동기 전후에 확인한다. 호스트 API가 없으면 해당 기능을 사용할 수 없다.
- 일반 route 소유 하위 트리 중 G7의 선언된 구조/ID/참조 규칙으로 안전하게 복제 가능한 범위를 지원한다. base/partial/extension 출처, 잠금, 반복 템플릿·iteration, 미선언 구조 및 미지원 사용자 지정 ID 규칙은 변경하지 않고 거부한다. NE3의 반복 항목 편집 지원을 조합 이식 지원으로 확대하지 않는다.
- 선택 노드와 모든 선언된 하위 구성의 renderer 존재, component capability, 허용 부모/자식, 포맷, 256 KiB 상한을 검사한다.
- 현재 템플릿과 manifest·병합 editor-spec·nesting의 canonical SHA-256이 저장 시점과 일치해야 한다. 변경된 조합은 자동 변환하지 않는다. 서명은 호환성 지문이며 권한 인증 수단이 아니다.
- 정적 조합은 동일 템플릿의 허용 위치에 재삽입한다. 표현식·번역 바인딩·동작·조건 또는 외부 DOM 참조가 포함되면 원래 layout에서만 사용한다. 가져올 때 이 범위를 다시 계산하므로 저장된 scope 변경으로 완화할 수 없다.
- G7 첨부의 동일 템플릿 상대 파일 URL과 실제 첨부 목록의 존재를 확인한다. 다른 템플릿·비정규 첨부 URL·삭제된 첨부는 거부한다. 일반 정적/외부 URL은 원본 값을 보존하며 외부 서버 생존 여부까지 검사하지 않는다.
- 새 ID를 발급하고 지원된 내부 참조를 새 ID로 연결한다. 일치한 route 출처만 삽입 대상 layout으로 재지정하며 출처를 삭제하거나 보호 영역을 복사하지 않는다.
- 검증 실패·선택 변경·응답 지연·취소 시 G7 원본과 이력을 변경하지 않는다. 허용된 변경 하나만 기존 G7 명령과 이력에 반영한다.

## 코드와 로딩

`native-editor/domain/composition.ts`가 전송 형식을 읽고, application이 저장/삽입 순서를 정하며, UI는 포트만 호출한다. `adapters/gnuboard7/compositions.ts`가 공개 호스트 계약을 검증하고 `compositionLibrary.ts`가 인증된 개인 API I/O를 담당한다. 서버의 domain/application/repository 계약에는 G7 구현을 import하지 않는다.

네이티브 기본 entry의 기존 gzip 8 KiB 한도를 유지한다. 개인 라이브러리는 **내 조합 열기**에서 별도 6 KiB 한도의 번들을 한 번 로딩하며 G7의 React를 공유한다. 로딩 실패는 재시도할 수 있고 기존 편집 기능은 유지된다. 이 번들은 G7 공개 등록 API를 추가하거나 기존 Puck 번들을 중첩하지 않는다.
