# 5차: 무료 베타와 첫 유료 킷 준비

전문서비스 사이트 킷 1개와 별도 평가용 ZIP, 무료 베타·설치·지원 안내를 구현했다. 제품 변경은 `31cb2c8494f8309101f9caaa4810fd445d412af9`에서 범위 통합 검증을 완료했다. 현재 결과는 판매 준비를 위한 기술 평가 후보이며 정식 판매, 외부 제작자 평가 완료 또는 편집기 전체의 제품 완성 판정이 아니다. 원격 push·배포·새 버전 릴리스는 수행하지 않았다.

## 제품 결과

- `jiwonpapa/professional-services` 0.1.0: 소개·서비스·진행 방식·문의 4페이지, 14개 섹션, 이미지 3장, 주소와 연결되는 헤더·푸터·메뉴를 제공한다. 기본 주소는 `/moro/about`, `/moro/services`, `/moro/process`, `/moro/contact`이며 홈 `/`는 바꾸지 않는다.
- 기존 `g7pb-site-kit/v1`와 `PageBuilderDocument`를 사용한다. 설치는 새 초안과 비활성 Site Part를 만들고, 각 페이지 발행과 공통영역 적용은 별도 명시 동작으로 유지한다. 설치 뒤 주소 변경에 따른 다른 문서 링크의 자동 재연결은 아직 없다.
- 무료 모듈 배포 파일 목록에서 전문서비스 manifest를 제외하고 무료 `company-starter`는 유지한다. 선택형 전문서비스 파일이 없거나 손상되어도 무료 킷 목록과 기존 설치 문서는 유지한다. 임의 외부 킷 가져오기나 결제·라이선스 서버를 추가하지 않았다.
- 평가용 ZIP은 addon 전용 이미지 경로를 사용해 무료 킷 이미지를 덮어쓰지 않는다. 이미지 먼저, manifest 마지막으로 SFTP 추가한 뒤 기존 사이트 킷 화면에서 설치한다. 고객 서버에서 Node·npm 빌드는 필요 없다.
- 최종 화면에서 짧은 브랜드 `모로`, 소개 제목 `일하는 방식부터`, 진행 제목 `협업 과정`을 사용한다. 기존 이미지의 실제 내용에 맞게 대체 텍스트를 수정했다. 이미지와 브랜드는 예시이며 실제 직원·고객·성과를 나타내지 않는다.

사용자 안내는 [무료 베타](../free-beta.md), [킷 설치·편집·지원](../kits/professional-services.md), [사이트 킷 계약](../site-kit-contract.md)에 기록했다. 지원 범위와 아직 결정하지 않은 판매 조건을 구분했다.

## 실제 문의 접수 오류 수정

G7 기본 템플릿의 첫 익명 방문에는 CSRF meta token과 XSRF cookie가 모두 없어서 실제 문의 POST가 419로 실패했다. 기존 G7이 사용하는 공개 `/sanctum/csrf-cookie` 경로로 세션을 준비하고, 발급된 cookie를 읽어 `X-XSRF-TOKEN`으로 제출하도록 수정했다. 기존 meta token 경로는 유지하며 CSRF 검증을 우회하지 않는다.

세션 준비 실패·토큰 누락·잘못된 cookie에서는 입력을 보존하고 안내한다. 제출 시점의 새 cookie를 사용하며, 세션 준비 중 화면이 해제되면 뒤늦게 접수하지 않는다. 관련 단위 검사는 문의 폼 15개와 기존 화면 수명주기 29개가 통과했다.

실제 브라우저는 새 익명 세션에서 bootstrap 204 → 문의 POST 201 → 저장된 접수 ID → 관리자 문의함의 미확인 항목을 확인했다. 접수 3건은 테스트용이며 실제 메일 수신자 설정이 없음을 실행 전에 검사했다. 문의 DB 저장은 성공했으나 `mail_status=failed`는 수신자 미설정에 따른 예상 결과다. 이메일 발송 성공이나 실제 고객 상담 완료로 보고하지 않는다.

## 검증 결과와 한계

환경은 로컬 `https://g7pb.test`, PHP 8.5.9, G7 7.0.9, 활성 `sirsoft-basic`이다. 모듈·package·lock 버전은 모두 0.33.1이며 이번 Unreleased 구현 SHA가 포함된 빌드다. 같은 버전 숫자의 과거 빌드, stock G7 신규 설치, 외부 VPS 및 다른 템플릿 조합의 수용 시험을 대신하지 않는다.

범위 계획으로 관련 Python 하네스·패키징, PHP 단위·통합, Vitest, 타입, 구조·경계, Pint, PHPStan, production build·asset 검사가 통과했다. 같은 명령·입력·환경의 성공은 하네스가 재사용했다. 전체 coverage 또는 전체 제품 회귀를 새로 실행했다고 주장하지 않는다.

| 브라우저 검사 | 결과 | 확인 범위 |
| --- | --- | --- |
| 사이트 킷 설치 | 6 passed | 무료·전문서비스 설치, 충돌 안내, 설치 결과 재진입, 편집·저장·재열기·미리보기·발행, 헤더·푸터 적용, 메뉴와 원래 세트 복원 |
| 실제 킷 문의 | 3 passed | 익명 첫 세션의 실제 접수와 관리자 문의함 |
| 공개 품질 회귀 | 3 passed | 등록된 접근성·시각 회귀 |
| 공개 컨트롤 회귀 | 1 passed | 기존 runtime 수명주기·문의 등 제어 시나리오 |

등록된 브라우저 13건은 재시도·skip 없이 통과했다. 킷 작성과 실제 문의 시나리오는 프로젝트 이름과 관계없이 PC 브라우저 설정을 사용한다. 킷 공개 페이지는 별도로 1440/768/390px을 방문한다. 모바일 편집기 지원 증거로 해석하지 않는다.

최종 제품 검증 뒤 소유한 검토용 설치만 사용해 원본 디자인 4페이지 × 3개 폭의 PNG 12장과 문의함 대화상자를 다시 촬영했다. 이 추가 시나리오는 1 passed, 40.9초이며 제목·공통영역·가로 넘침·브라우저 실행 오류를 확인하고 진입 모션 완료 후 캡처했다. 실제 화면을 직접 확인했으며, 종료 시 기존 활성 공통영역을 복원했다. 검토용 페이지에 다시 접속하면 복원된 원래 공통영역이 보이는 것은 정상이다. 이 확인은 외부 제작자의 최종 디자인 승인과 별개다.

원래 존재했던 모듈 소유 8개 테이블의 **5,173행은 누락 0, 변경 0**이다. 세트의 활성 상태도 비교했고 `g7pb_site_part_sets.updated_at`·`updated_by`만 제외했다. 검증으로 새로 생성한 문서·발행본·접수는 보존했다. G7 전체 DB 비교나 전체 DB 백업을 수행했다는 뜻은 아니다.

## 패키지와 재현 근거

최종 평가용 파일은 `output/releases/site-phase5-final-20260907/jiwonpapa-professional-services-0.1.0-evaluation.zip`과 같은 이름의 `.sha256`이다. 7개 payload 파일과 `SHA256SUMS`를 포함한다. manifest·이미지 3장·설치 안내·무료 베타 안내·`PRODUCT.json`의 체크섬을 모두 확인하고 별도 폴더에 푼 파일을 실제 PHP Adapter로 읽어 4페이지·3이미지를 확인한다. 이전 평가 ZIP은 덮어쓰지 않는다.

무료 릴리스 payload의 실제 목록도 확인해 무료 starter 포함·전문서비스 manifest 제외를 검증했다. 무료 모듈의 정식 릴리스 archive를 생성하거나 배포한 것은 아니다.

주요 증거는 저장소의 로컬 `output/playwright/site-phase5-20260907/` 아래 보존한다.

- `final-verification.log`: `31cb2c8`의 scoped `integration-verify` 완료. 기준 SHA는 `a4a43d716a5c9ea2e13e7461b6d3dfe4d7339014`다.
- `integrate-final-batch.log`: 문의 수정과 최종 모바일 문구의 통합 및 관련 브라우저 결과.
- `environment-verified.json`: 실제 PHP·G7·활성 템플릿 확인.
- `before-source-hashes.json`, `after-source-hashes.json`, `source-preservation.json`: 원본 8개 테이블의 비교 근거.
- `review-final/run.log`, `review-final/results/review-reviews-the-final-o-e6695--kit-at-three-public-widths/`: 최종 12개 화면, 문의함 화면과 소유 설치 기록.
- `package-final.json`, `package-verification-final.json`, `package-loader-final.json`: 최종 ZIP 식별자·전체 체크섬·분리 배포 목록·실제 Adapter 로딩 결과.
- `report-integration.log`, `report-verification.log`: 안내 문서 통합과 최종 문서 범위 확인.

등록된 Site Kit 최종 브라우저 증거는 `output/playwright/gates/site-phase5-integration-20260907/4253b2abdc3d813bb38d1fdd503d4fa9157bba64220697ab321d2b74eb3997dc/03cd57348d3f42d1a5db7856c8da1a1f/`에 있다. 실제 문의 증거는 같은 integration 디렉터리의 `16c873cdc49b0487c18d7769a1fef8ae38330353453281cf107cd54cdd803aac/862aa05537e64e09af51cfbff78f3ce2/`에 있다. 실패했던 초반 선택자·캡처 시도도 보존하되 최종 성공 근거와 혼동하지 않는다.

## 보류된 판매 조건과 현재 개발 방향

가격, 이용 가능한 사이트 수·제작 대행·원본 재판매 범위, 업데이트·지원 기간, 구매 전달·재다운로드·환불 운영, 자산 배포 권한 검토가 남았다. 독립 외부 제작자가 안내만으로 설치·수정·발행하는 평가와 최종 디자인 승인도 아직 없다. 이는 정식 판매 전 별도 기준이며 이번 기술 검증으로 승인 처리하지 않는다.

전체 User Template·풀 테마 상품 제작을 다음 차수로 편성했던 방향은 철회했다. 현재 후속 작업은 [편집 고도화 실행계획](../productization/editor-plan.md)을 따른다. 위 판매 조건은 판매를 재개할 때 검토할 보류 항목이며 현재 실행 순서가 아니다.
