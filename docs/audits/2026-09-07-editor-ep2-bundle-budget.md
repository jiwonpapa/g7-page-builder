# EP2-01 편집기 번들 예산

2026-09-07. 최종 통합 검사는 Linux Node 24.19.0 `gzipSync` 기본 옵션을 기준으로 합니다.

| 측정 대상 | gzip bytes | 환경 / 해석 |
|---|---:|---|
| 연결 전 `fabda883` 빌드 | 501,966 | 초기 macOS 측정 기록 |
| 초기 EP2-01 후보 | 504,142 | 초기 macOS 측정 기록, 최종 통합 판정에 사용하지 않음 |
| 최종 후보의 동일 JS 파일 | 504,125 | macOS Node 24.19.0, zlib 1.2.12 |
| 최종 후보의 동일 JS 파일 | 506,114 | Linux Node 24.19.0, zlib 1.3.2.1-motley-3246f1b |
| 최종 편집기 JS 한도 | 507,000 | Linux 측정 대비 886 bytes 여유 |

최종 파일은 1,755,267 raw bytes이며 SHA-256은 `0d272d3cdeaf0ac26660c51ca2aa9db9f6a2e4686ddb7143ad4c0aa6b4660887`입니다. 동일 파일을 두 런타임에서 읽어 위 수치를 재확인했습니다. Node 버전이 같아도 압축 라이브러리 버전이 달랐습니다. 초기 macOS 후보만으로 정한 505,000 한도는 Linux 통합 검사의 506,114 bytes를 수용하지 못했으므로 최종 판정 환경의 실측에 맞춰 정정합니다. 서로 다른 압축 환경의 수치를 기능 증가량으로 비교하지 않습니다.

기존 500,000 한도 대비 최종 상한 증가는 7,000 bytes (1.4%)입니다. 아이콘·목록·배지의 스키마·필드·변환·렌더 코드를 포함하며 새 의존성이나 페이지 레이아웃 엔진을 추가하지 않았습니다. 자동 상한 갱신은 없습니다. 후속 차수의 증가는 별도로 측정하고 검토해야 합니다.

공개 runtime JS 합산 34,000 한도와 다른 번들 한도는 그대로입니다. 이 수치는 전송 크기 검사이며 성능·접근성·제품 완성 승인으로 해석하지 않습니다. 최종 통합 Linux 빌드가 이 상한을 실제로 통과해야 합니다.
