# 코드 구조 개선 차수

기준: `0a6fcbae69ad0c0ad93aea145c8899c4b001ecfb`, 2026-09-02. [이전 코드 감사 개선](2026-09-02-code-audit-remediation.md)의 후속 작업이다.

## 범위와 진행 방식

기존 블록 콘텐츠의 문구·이미지·샘플·프리셋 품질은 검사하지 않는다. PHP·TypeScript·JavaScript·CSS의 책임 분리, 검증 경계, 재사용, 테마와 하네스가 대상이다. 합성 문서로 코드 동작을 검증한다. 제품 기능 재기획, 운영 배포, 운영 데이터 준비·변환은 이번 코드 개선과 별도다.

차수는 아래 순서로 진행한다. 각 실행 단위는 정확 파일 24개 이내의 독립 worktree와 scoped task로 소유하고, 관련 검사 → Local 통합 → 통합 검증을 마친 뒤 다음 단위로 넘어간다. 한 차수가 여러 단위로 나뉘면 `1-A`, `1-B`처럼 기록한다. 앞 단위의 코드·검증이 완료되기 전에 의존하는 다음 구현을 시작하지 않는다.

파일 축소만으로 완료하지 않는다. 도메인 규칙·상태·렌더·외부 변환의 소유자가 명확해야 하고 기존 동작과 직렬화 형식이 유지되어야 한다. 단언을 다른 단언으로 바꾸거나, 색마다 이름만 붙이거나, 예외를 다른 파일로 옮겨 수치만 줄이지 않는다. 신규 예외·기존 상한 증가·전체 검사로의 자동 확대를 금지한다.

## 시작 부채

정적 진단 1,079건은 실행 오류 개수가 아니다. 코드 수정 전 마지막 감사와 현재 소스가 일치하는 기준을 사용하며, 차수별 실제 감사 수치로 갱신한다.

| 규칙 | 시작 진단 |
| --- | ---: |
| 색 리터럴 | 908 |
| `!important` | 135 |
| selector 우선순위 | 16 |
| TypeScript 우회 단언 | 9 |
| 파일 크기 | 11 / 8개 파일 |

크기 대상은 `documents/types.ts`, `PuckEditorAdapter.tsx`, `catalogBlocks.tsx`, `richTextEditing.tsx`, `PageBuilderManager.tsx`, `pageEffects.ts`, `HtmlDocumentCompiler.php`, `page-builder-editor.css`다. TS의 줄 수와 AST 크기가 동시에 초과한 경우 진단이 둘이므로 파일 수와 구분한다.

## 운영·인프라 경계

인증된 G7 runtime이 없는 hosted CI는 실제 브라우저 통과로 인정하지 않는다. 차수별 제품 검증은 소유권을 확보한 Local runtime에서 수행한다. hosted CI용 runtime/인증과 최초 Site Part 발행 결과 이행은 별도 환경 결정·실행 증거가 필요하며, 로컬 코드 정비만으로 해결됐다고 보고하지 않는다.

| 계획 | 작성 | 기준·순서·완료 조건 정의. 구현 완료가 아님 |

완료된 단위의 제출 SHA, 통합 SHA, 선택 검사, 부채 전후 수치를 이 문서 또는 연결된 차수 보고서에 기록한다. 다음 차수의 계획을 작성했다는 이유로 해당 차수를 완료 처리하지 않는다.
