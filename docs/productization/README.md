기준일: 2026-08-31. 시작 SHA: `8b75d3a654638bfeb932985f67f8106ef05c8c42`.

사용자는 G7 참고 설계를 포함한 8차 개선 계획을 1차부터 추진하고 차수별로 자동 커밋하도록 지시했습니다. 계획의 실행 단위는 유지하고, 차수별 결과를 섞지 않습니다. 소스 제출·통합·제품 합격·운영 배포는 서로 다른 상태입니다.

## 차수 진행과 커밋

1. 차수별 정확한 파일 범위와 검증 profile을 소유한 worktree에서 작업합니다.
2. 필수 검사 뒤 `make task-submit TASK=<id>`로 자동 커밋·제출합니다. 수동 stage/commit으로 우회하지 않습니다.
3. integration/runtime 소유자가 통합 게이트를 통과시킨 뒤 다음 구현 기준 SHA를 정합니다.
4. 합의된 기술 범위 안에서는 이번 추진 지시에 따라 순차 진행·자동 커밋합니다. 범위 확대·파괴적 이행·운영 배포·사람의 시각 승인은 별도 권한/증거 경계를 유지합니다.
5. 기존 활성 작업의 dirty 파일·lease를 가져오거나 해제하지 않습니다. 차수의 필수 선행 조건이 충족되지 않으면 제출된 산출물과 남은 조건을 보고하며 다음 차수 완료로 건너뛰지 않습니다.
