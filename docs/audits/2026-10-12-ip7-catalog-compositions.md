# IP7 내장 구성 템플릿과 공통영역

상태: **구현 착수, 미완료**. 기준은 IP6 완료 SHA `2553987c1a08b544dff38a1f4cfe77599ea69254`다. 확정 스펙 SPEC-12·SPEC-13과 IND-07의 contract·browser·compatibility 증거를 모두 확보한 뒤 완료한다.

## 범위와 보존 경계

현재 내장 manifest의 모든 block과 preset을 열거하여 편집 가능한 구성·반복 템플릿·보호된 실행 기능·기존 원본 이행 경로를 대응시킨다. Hero·Card·ImageText뿐 아니라 반복·동적 블록과 PB Header/Footer를 포함한다. 대표 사례만 통과하거나 미구현을 지원 제외로 바꾸어 완료하지 않는다.

구성 템플릿의 삽입본은 PB 문서가 소유하는 요소 트리다. 내부 디자인은 기존 v3 명령·Puck 이력·정밀 Inspector로 편집하고, 서비스가 반환한 데이터와 인증·폼·슬라이더 등의 실행 책임은 디자인 원본과 분리한다. 공통영역은 본문과 별도 원본·revision을 유지한다.

기존 v1/v2·Site Part는 읽기만으로 전환하지 않는다. 사용자가 전환을 선택했을 때 원본 revision·알 수 없는 필드·블록별 매핑을 검사하고 초안 후보를 만든다. 미지원 데이터가 있으면 전체 전환을 중단하며 원본 snapshot·복원 경로와 마지막 정상 발행본을 보존한다. G7 소유 원본·코어·테마 파일·운영 배포는 변경하지 않는다.

## 작업 분할과 합격 조건

1. 전체 카탈로그·프리셋·Site Part의 필드/슬롯/동작을 조사하고 누락을 검출하는 계약과 대응표를 구현한다.
2. 필요한 v3 구성·반복·보호 동작 계약을 PHP/TS 공통 fixture로 연결한다. 계약 변경은 shared-contract lease 아래 별도 task에서 검증한다.
3. 기존 요소 편집·단일 이력에 구성 삽입과 내부 편집, 명시 전환·거부·복원을 연결한다.
4. 전체 대상의 저장/재열기 및 렌더 의미를 검증하고 실제 브라우저에서 내부 편집·Undo/Redo·공통 shell 미리보기를 확인한다.

task마다 정확한 파일을 claim하고 공식 제출·통합을 사용한다. 완료 전 실제 제출/통합 SHA·명령·결과·증거 경로를 이 기록과 진척 원장에 반영한다. 이 착수 기록 자체는 기능 구현 또는 검증 성공의 증거가 아니다.

기본 구성은 기존 문서 변환이 아니라 **새 v3 트리 삽입**이다. `basicCompositions.ts`의 13종 외에 내장 49개·99개 전체 편집을 완료했다는 의미가 아니다. 카탈로그 대응표도 분류 계약이며, 변환기 또는 UI 구현 증거로 대신하지 않는다.

이행 세션은 원본 bytes/revision을 보존하고 검증된 후보에만 일회성 적용을 허용한다. 저장 응답이 늦어도 다른 문서에 적용하지 않으며, 불확실한 쓰기를 자동 재시도하지 않는다. 이 단계에서는 주입 포트로 24개 단위 시험을 수행했으며, 실제 서버 이행·복원 완료를 주장하지 않는다.

## 기본 구성 실제 브라우저 검증

실행 명령: `make task-integrate-batch TASKS=ip7-basic-compositions-20261012,ip7-composition-verification-20261012 INTEGRATION_TASK=integration-ip7-20261012`.

Node 24·PHP 8.5·고정 Chromium의 Local runtime에서 G7 없는 실제 독립 mount를 빌드하고 주입 저장 포트와 실제 PHP `DraftRenderer`를 사용했다. 13개 새 구성 각각에서 내부 제목 스타일 변경, Undo/Redo, 저장·재열기, 읽기 전용 삽입 거부와 360/768/1280px의 캔버스·React preview·PHP 출력을 비교했다. 기존 17개 편집 시나리오도 유지했다.

- **90개 통과, 실패/skip/flaky 0**: 30개 시나리오 × desktop/tablet/mobile 프로젝트.
- **117개 비교 기록의 최대 치수 차이 0 CSS px**: 13개 구성 × 3개 폭 × 3개 프로젝트. 합격 기준 1px는 변경하지 않았다. 각 노드의 태그·문자·주요 계산 스타일도 비교했다.
- 관련 기본 구성 15개·편집 UI 10개·카탈로그 105개 단위 시험, 타입·구조 검사 통과. 이행 세션 24개 시험은 별도 통합에서 통과했다.
- 첫 실행에서는 9개 구성 × 3개 프로젝트의 정렬이 달랐다. Puck 슬롯 CSS의 기본 `width/height:100%`가 지정되지 않은 authored 크기에 개입한 것이 원인이었다. 캔버스 슬롯에만 기본 `auto`를 적용하고 명시 크기의 우선순위를 보존했다. 별도 회귀 시험과 동일 90개 브라우저 시험으로 확인했다.
- PC 스크린샷과 모바일 포스터 화면을 육안 확인했다. 삽입용 기본 문구/샘플 자산이며 상품 테마 디자인 검수로 보지 않는다.

## 남은 수용 조건

반복·동적 블록과 전체 내장 구성, PB Header/Footer 상세 편집 및 shell preview, 실제 기존 원본의 명시 이행·거부·복원은 아직 완료되지 않았다. IP7 원장은 `in_progress`로 유지한다. 뒤이어 IP8 미디어/사용자 구성, IP9 실제 저장·발행/복구, IP10 전체 제품 수용을 순서대로 진행한다. G7 코어·테마 원본·운영 서버 변경이나 배포는 실행하지 않았다.
