# Visual UI Editor 기본 편집 기능 감사

상태: **0.33.0 코드 범위 완료, 기술 베타 판정**. 제품 통합 기준은 `bd719c25a19f29eadbe842f9cc1df65b31ef33f8`이다. 이 문서는 코드·관련 브라우저 검증 결과를 기록하며, 릴리스 패키지·Git push·g7devops.com 배포와 운영 smoke는 별도 릴리스 영수증으로 판정한다.

## 범위와 제외

이번 범위는 PAGE 설정 UX, 편집 상단 명령 체계, 문서 제목과 공개 주소, PC 편집 작업면, 공통 1280px 셸, 중첩 블록 구조 명령과 저장 수명주기다. 기존 블록의 문구·이미지·샘플 품질, 새 블록, 블록 라이브러리 확장, 사용자 패턴, Page Kit 추가·개선은 포함하지 않았다.

코드 변경은 기준 `8e2a3ad74a302afd195d2ae56834d3feca45f97b` 이후 35파일, 701줄 추가·192줄 삭제다. G7 Layout Editor 구현이나 저장 엔진을 가져오지 않았고, 독립 `PageBuilderDocument`와 Puck adapter 경계를 유지했다.

## 검증 증거

인증된 Local G7 runtime과 실제 production build 자산으로 다음 시나리오가 통과했다. skip·flaky·실패를 성공으로 계산하지 않았다.

| 묶음 | 결과 | 검증 내용 |
| --- | ---: | --- |
| `editorDocumentBoundary` | 2/2 | 문서 경계와 저장 원본 |
| `editorLayoutParity` | 27/27 | PC·태블릿·모바일 편집/공개 레이아웃 |
| `editorStructureTheme` | 5/5 | 중첩 선택·삽입·이동·복제·삭제·재열기·테마 |
| `pageBuilderLifecycle` | 3/3 | 생성·편집·발행·복원과 3열 내부 Stack |
| `siteShellProductQuality` | 18/18 | 셸 정렬, 계정 상태, 로그인·로그아웃, 독립 뷰어 |
| `globalSiteShellRoutes` | 1/1 | 대표 G7 사용자 라우트 전역 적용과 폴백 |
| `sitePartLifecycle` | 5/5 | Header/Footer 편집·발행·세트 전환·복원 |
| `mobileNavigationQuality` | 9/9 | 메뉴 방식·포커스·스크롤·WebKit 모바일 |
| `publicRuntimeLifecycle` | 1/1 | 공개 셸 제어와 명시적 서비스 요청 |

공개 셸 검증은 테스트 소유 Header/Footer 세트를 생성·발행·활성화한다. 시작 전 활성 포인터와 감사 필드를 기록하고 종료 시 원래 값을 복원하며, 공유 문서 본문이나 기존 발행 결과를 수정하지 않는다.

정적 구조 재감사는 제품 소스 367파일에서 신규 위반 0, 기존 부채 220, 해소 후보 0으로 통과했다. 220건은 `CSS-COLOR` 184건과 `CSS-IMPORTANT` 36건이며 해결 완료로 계산하지 않는다. 신규 금지 단언·계층 역참조·색상 복제·우선순위 증가는 허용하지 않았다.

## 성숙도 판정

핵심 Visual UI Editor 범위는 알파를 벗어나 **기술 베타**다. 중첩 구조의 기본 생성·선택·이동·복제·삭제와 저장 왕복이 실제 브라우저에서 닫혔고, PAGE 설정과 작업면도 일관된 편집 규칙을 갖췄다. 따라서 “블록을 배치만 할 수 있고 구조를 편집할 수 없는 데모” 상태는 아니다.

전체 제품은 아직 상용 완료로 판정하지 않는다. 기존 CSS 부채 220건, 대형 문서 장시간 편집·다중 세션 복구·브라우저 전체 조합·보조기술 전수 검증, 과거 스키마 장기 호환과 운영 soak가 남아 있다. 블록 콘텐츠와 Page Kit의 상품성도 이번 범위에서 검증하지 않았다. 상용 판정은 운영 배포 성공만으로 올리지 않고 이 잔여 항목의 별도 승인과 실제 사용자 편집 검증을 요구한다.

현재 구조에서는 후속 개선이 가능하다. 문서 명령, Puck adapter, 선택 정책, 공통 필드, 테마 토큰, 소유형 브라우저 픽스처가 분리되어 있어 개별 버그 패치가 다시 거대 조정 파일과 공유 DB 상태에 결합되지 않는다. 다음 우선순위는 핵심 편집기 회귀를 유지하면서 성능·접근성·복구와 잔여 CSS 부채를 줄이는 일이며, 새 블록과 Page Kit는 그 뒤에 진행한다.
