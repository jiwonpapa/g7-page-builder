# IP7 공통 폼 브라우저 수용 정의

## 시간 경계의 결정적 검증

`09cf9804b5eaaab257f70697030f48534286fb2a7258693e54221a5a0f4e5b59/9bbcc237908842a18397b4c4a029dd5a` 실행은 다시 38/39였다. tablet/none의 거부 시험 중 시각을 요청 직전에 계산했지만 실제 요청은 10:48:37.523Z에 시작해 1,621ms 뒤 처리됐고 서버 응답 시각은 10:48:39 GMT였다. 초 단위 최소 2초가 경과하면 201 접수가 제품의 올바른 결과이므로, 네트워크 왕복 중 경계가 바뀔 수 있는 시험이었다. 정상 문의 접수·저장 경로의 실패로 해석하지 않는다.

보존 교체 `ip7-form-time-boundary-proof-20261013`은 브라우저의 거부 입력을 현재보다 하루 뒤인 `started_at`으로 바꾼다. 미래 시작 시각은 같은 경과 시간 guard에서 거부되며 일반적인 요청 지연으로 합격/거부가 바뀌지 않는다. 이는 정확한 0초 경계의 E2E 증거가 아니다. 정확한 경계는 `PublicationPersistenceTest::test_element_form_publication_uses_existing_persistence_and_fixed_inquiry_validation`에서 Laravel 시각을 고정하고 0초·미래 시각 거부 및 최소 1초 경과 시 접수를 세 shell 모두 검사한다.

브라우저의 `[404,404,422,422,422,419]` 기대값, 실제 정상 접수, CSRF, 소유권, 개인정보 동의, honeypot 및 출력 1px 기준은 유지한다. 제품 설정·제품 소스·재시도는 변경하지 않는다. 예상 밖 접수의 소유 ID 수집과 finally 보관 처리도 유지한다. 정의/수집 검사는 실동작 증거가 아니며 다음 공식 통합에서 재검증한다. 직전 실패의 통합은 원복됐고 JW 테마 재활성화와 코어 기준 파일 동일 해시를 확인했다.

## 요청 직전 시각과 실패 fixture 소유권

후속 `758c965035302639a8711bae595f87f424f1bcb0accb91b161221ca10b6e716e/ca8e0567eaba4e7db2091dbb76d6abe3` 실행은 38/39였다. 세 프로젝트의 실제 입력 보존·문의 접수 경로는 지나갔으나 tablet/none의 추가 거부 결과가 `[404,404,422,422,201,419]`여서 실패했다. visitor trace에서 거부 요청 시작 09:42:42.480Z와 최소 시간 요청 09:42:44.159Z를 확인했다. 후자의 `started_at`은 앞선 네 요청 전에 초 단위로 계산해 두어 이미 2초가 지난 상태였다. 제품 거부 기준을 완화하거나 성공 응답을 거부로 취급하지 않는다.

보존 교체 `ip7-form-request-clock-20261013`은 같은 39개 시나리오에서 최소 작성 시간 요청 **직전**에 시각을 만든다. 기존 기대 상태·CSRF·입력 보존·실제 저장·1px 기준을 유지한다. 거부 시험이 예상 밖으로 성공한 경우에도 반환된 ID를 소유 목록에 넣은 뒤 assertion을 수행하여 finally에서 문의를 보관 처리한다. 삭제는 하지 않는다. 이전 실패의 추가 문의는 ID와 시험 소유 slug/message를 확인한 후 별도 공식 관리자 API로 보관·읽기 검증한다.

이 변경은 시험 정의이며 자체로 실제 브라우저 성공을 뜻하지 않는다. 직전 통합은 원복했고 원래 JW 활성 상태 및 코어 기준 파일 두 개의 동일 해시를 확인했다.

직전 실패가 추가 생성한 문의 `90761412-c94f-4f10-bf9b-d7aaa7b10bd5`는 공식 관리자 API에서 `g7pb-form-none-1791884550558-78f0a750` 및 시험 문구를 대조한 뒤 PATCH로 `archived` 처리하고 다시 읽어 확인했다. 자료를 삭제하지 않았으며 시험 외 문의는 수정하지 않았다.

## 독립 편집기

빈 카탈로그에서 입력·라벨 삽입, 설정과 즉시 Undo/Redo를 실행한다. 공유 canonical fixture의 요소 트리를 불러온 뒤 UI로 제출 역할을 안정 ID에 연결하고, 잘못된 입력 종류의 원자적 거부·취소, 라벨 직접 입력, 반응형 크기/글자 크기, 저장·재열기·읽기 전용을 검사한다. 전체 폼을 처음부터 UI로 조립했다는 증거로 혼용하지 않는다.

1280·768·360px에서 캔버스·React 미리보기·PHP 초안의 텍스트·글자 크기·모든 요소의 상대 좌표와 크기를 1px 기준으로 비교하고 JSON/스크린샷을 남긴다. 편집 중 native 입력의 입력 소유권 차단과 미리보기의 전송 부재를 확인한다.

## 실제 G7 저장·출력

각 `none`, `template`, `builder` 페이지를 실제 UI로 만들고 인증된 초안 API로 공유 요소 fixture를 초기화한다. UI에서 라벨·안내·모바일 높이·문의 분류를 변경하고 즉시 Undo/Redo, 저장·재열기·명시적 발행을 실행한다. 세 폭에서 실제 공개/미리보기와 편집 캔버스를 비교한다.

익명 브라우저의 정상 CSRF 경로로 실제 문의를 접수하고 관리자 문의함에서 읽어 확인한다. 외부 메일 수신자가 설정되어 있으면 시험을 거부한다. 잘못된 소유 ID/분류, 개인정보 미동의, honeypot, 미래 시작 시각의 미경과 제출, CSRF 부재의 거부를 검사한다. 정확한 최소 작성 시간 경계는 위 고정 시각 PHP 시험으로 검증한다. 시험이 만든 문서와 문의만 공식 API로 archive하며 삭제하지 않는다.

## 검증 경계

다음 설치형 실행은 기존 30개 통과·새 폼 9개 실패였다(`output/playwright/gates/integration-ip7-20261012/d2be4ce28c397b84d94c7a66741e08247a050783e740cb7c9d1192d120c558e5/06582ce555ec4ab7a3847072bb00a818/results.json`). none/builder의 실제 제출 419와 template의 40px 폭 차이가 남았다. 같은 시기 다른 채팅에서 공유 G7을 7.1.0으로 갱신하고 활성 테마를 바꿨으므로 이 실행을 안정된 테마 호환 증거로 사용하지 않는다. 코어/테마 갱신은 이 PB task가 실행한 변경이 아니다.

G7 없는 별도 호스트의 폼 시험은 Puck의 drag root가 pointer-events를 auto로 소유하는 것을 확인했다. CSS 선언값 대신 실제 클릭 선택·문서 무변경을 검사하도록 보완했고, 체크박스 클릭 시 체크되는 native 기본 동작을 재현했다. readonly만으로 checkbox 동작이 막히지 않으므로 제품의 편집 입력 소유권을 보완한 뒤 재검증한다. 공개 문의는 공식 세션 갱신 204를 검사하고, 후속 거부 요청도 갱신된 cookie를 사용한다. 1px·CSRF·저장 수용 기준은 유지한다.

Local의 `integration-ip7-20261012` runtime lease에서 계약·제품·시험 task를 함께 통합한 뒤 실행 결과와 실패/수정 이력, 실제 스크린샷 판독을 별도 통합 증거에 기록한다. 공통영역 문의 capability 부재, IP7 전체 카탈로그/이행, IP8~IP10은 이 시험의 완료 범위가 아니다. G7 코어 변경·운영 배포·기존 문서 자동 전환은 없다.
