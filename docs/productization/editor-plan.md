# G7 네이티브 페이지 편집 확장 개발 계획

<!-- editor-plan:native-editor-20260907 -->

상태: **NE1~NE6 완료(6/6)**. PB 0.35.0과 검증한 G7 공개 호스트를 g7devops.com에 배포하고 실제 운영 일반 페이지의 네이티브 편집·Undo·재열기 및 공개 출력을 확인했다. 상세 증거와 지원 한계는 [NE6 기록](../audits/2026-09-08-native-editor-ne6.md) 및 [진척 원장](editor-progress.json)을 따른다. 계획 차수 완료는 모든 테마/구조 지원이나 전체 제품 상용 완성 판정이 아니다.

[편집 정책](editing-policy.md) · [개발 헌법](../development-constitution.md) · [진척 원장](editor-progress.json) · [표시판](editor-progress.md) · [코드 근거](../audits/2026-09-07-native-editor-governance.md)

## 실행 규율

1. 한 차수의 의존성·수용 기준을 충족한 뒤 다음 차수를 진행한다. 차수당 구현 task는 정확한 24개 이하 파일 scoped lease로 나눌 수 있으며 이 표의 후보 경로는 소유권이나 파일 생성 지시가 아니다.
2. G7 측 공개 계약이 필요한 작업은 이 저장소 내부 import나 임시 SDK로 우회하지 않는다. 실제 공개 API·버전·서명·소유자·실패 의미를 확인하고 부족하면 원인과 선행 작업을 기록한다.
3. 각 차수에서 실제 편집·Undo·저장·재열기를 검증한다. 성공 입력 재사용과 실패 downstream 재실행을 유지하며 관련 없는 전체 검사·콘텐츠 증설로 범위를 넓히지 않는다.
4. 정책/소스/통합/실동작/배포 증거를 구분한다. 문서 checker는 완료 근거 형식·연결을 확인하며 제품 성공이나 현재 HEAD를 자동 보증하지 않는다.
5. 기존 [EP 계획](editor-plan-puck-20260907.md)과 [4/11 완료 원장](editor-progress-puck-20260907.json)은 해시로 보존한다. 기존 미완료 요구를 완료나 영구 제외로 바꾸지 않는다.

선행: H01~H04 공식 계약 확보; G7 수정은 별도 승인 필요. 수용 기준 `NAT-01`.

- H01~H03의 문맥·경로·명령 계약을 실제 G7 공개 API와 고정 기준 SHA로 확보한다. H04 패널·선택·내보내기 계약도 서명·소유자·제공 방식을 확정한다.

선행: NE5. 수용 기준 `NAT-06`.

**마감:** 검증한 G7/지원 템플릿 조합과 기존 PB 문서·발행본·주소가 공존. 실제 동시 저장·권한·장애 복구·반응형 공개 출력 통과 후 승인 범위의 릴리스와 운영 재열기/공개 결과 증거 기록.

- v1 자동 전환 금지, v2의 기존 공유 슬롯 정책·메타데이터 보존·서버 검사·컴파일 경계를 유지한다.
- 고정 Puck 0.23.0의 250ms 이력 기록 지연을 좁은 빌드 보정으로 제거한다. 단일 Puck history를 사용하며 새 Undo 엔진을 추가하지 않는다. 버전 소스 지문이 다르면 빌드를 실패시켜 재검토를 요구한다.
- 명시적 편집 명령마다 즉시 기록한다. 선택/미리보기 같은 비기록 동작은 Undo 단계를 추가하지 않는다. 빠른 연속 Undo/Redo, 새 편집의 redo 분기 폐기, 저장/재열기를 검증한다.
- 실제 브라우저에서 기다림으로 결함을 피하지 않는다. 반복 구조 편집은 기존 Hero 회귀도 함께 검사한다.
- 마감은 관련 검증·차수 커밋·로컬 통합이다. actions/Card·새 블록·킷·G7 코어·운영 배포는 제외한다.

완료 증거(로컬 통합·실제 동작, 운영 미배포): [4차 기록](../audits/2026-09-08-editor-ux4.md).

## 독립 PB 개선 5차 — 단일 Card 내부 구성 (UI5)

<!-- editor-item:UI5 -->
<!-- editor-acceptance:UI-05 -->

선행 UI4. `content.card-01` 단일 Card의 media/body/actions 구역을 구현한다.

- media에는 Image, body에는 Heading/RichText/Icon/List/Badge/Divider, actions에는 Buttons를 종류별 0~1개 허용한다. Buttons 자체 1~3개 제한을 유지한다.
- root 및 Section/Columns/Stack의 허용 위치에서 사용하고 전체 자식 포함 깊이 4를 유지한다. CardGrid를 단일 Card로 대체하거나 자동 변환하지 않는다.
- 기존 Puck 명령·이미지/링크 picker·Undo·문서 저장을 재사용한다. 전체 Card 링크는 지원하지 않아 중첩 링크를 만들지 않는다.
- 실제 삽입·편집·이동·삭제·Undo·저장/재열기 및 공개 출력을 확인한다. 구역별 허용 타입/개수와 원본 보존은 TS/PHP에서 함께 검증한다.
- 기본 구조를 노출하는 Card 한 종류만 추가한다. 디자인 킷·테마·G7 코어·다른 컴포넌트 actions 확장·운영 배포는 제외한다.

완료 증거(로컬 통합·실제 동작, 운영 미배포): [5차 기록](../audits/2026-09-08-editor-ux5.md).
