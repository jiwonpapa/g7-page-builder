## 원본과 버전

PageBuilderDocument의 안정 ID·block identity/version·slots·자산 참조를 출발점으로 한다. DOM selector, 벤더 element 객체, 화면상 index는 영속 노드 식별자가 아니다. 편집 잠금·레이어 이름·스타일·레이아웃처럼 저장할 정보와 선택·줌·포인터·모달 같은 세션 정보를 구분한다.

새 정밀 디자인 계약은 **문서 v3 목표**로 개발한다. 정확한 wire 필드와 PHP/TS 스키마는 IP2에서 공통 fixture로 고정한다. 이번 정책 작업은 실제 schema_version, compiler_version 또는 모듈 버전을 변경하지 않는다. 기존 v1/v2·Site Part 버전은 각자의 읽기/쓰기/출력 의미를 보존하며, Site Part도 상세 편집 계약 도입 시 별도 버전·이행을 갖는다.

구성 템플릿은 기본 노드 트리와 디자인 값의 조합이다. 재사용 가능한 정의와 삽입된 인스턴스를 구분한다. 첫 제품 범위의 사용자 구성은 독립 사본이며, 원본 수정이 모든 페이지로 즉시 전파되는 연결형 컴포넌트는 별도 후속 계약 없이는 추가하지 않는다.

미지원 외부 블록·확장 필드를 조용히 삭제하거나 평문화하지 않는다. 알려지지 않은 데이터는 기존 포맷에서 보존하고, 변환할 수 없는 문서는 진단 후 이행을 중단한다.

## 레이아웃과 값의 의미

| 속성군 | 확정한 의미 |
|---|---|
| 크기 | auto/내용 맞춤/남은 공간 채움/명시 길이, width/height/min/max와 aspect ratio |
| 길이 | 허용 속성별 px·%·rem·vw·vh; 유한 숫자만, 단위 없는 임의 문자열 금지 |
| 여백 | padding/margin 각 변, row/column gap; 기본 패딩/간격은 음수 금지, 음수 margin은 의도적 겹침용 typed 값 |
| Flex | 방향·wrap·주축/교차축 정렬·grow/shrink/basis와 노드 순서 |
| Grid | 숫자/길이/fr 및 typed minmax 트랙, 열/행 span·배치; raw CSS 수식 입력 금지 |
| 외형 | 토큰 또는 검증한 명시 색, 단색/typed gradient/이미지 배경, 개별 border/radius, typed shadow, opacity |
| 글자 | 허용 font family/weight, 크기·행간·자간·정렬·장식; 링크와 제목 단계는 의미 데이터로 별도 저장 |
| 이미지 | 자산 참조·alt·비율·object-fit·초점 위치, 비파괴적 자르기 표현 |
| 겹침 | 명시적 positioned Container 안의 absolute 자식, typed inset/z-order/rotation; 부모 변경 시 좌표 변환 검증 |
| 표시 | breakpoint별 hidden과 편집 잠금; 숨긴 노드도 레이어에서 찾아 복구 가능 |

값별 허용 범위·정밀도·단위 환산·기본값은 IP2의 단일 버전 명세에서 PHP/TS가 공유한다. 숫자 범위를 UI 한 곳에만 두거나 React와 PHP에 독립적으로 복제하지 않는다. NaN/Infinity·과도한 크기/깊이·순환·잘못된 URL은 서버에서도 거부한다. 기존 문서의 한도를 정책 문서만으로 완화하지 않는다.

그룹은 레이아웃 Container이고 선택 묶음은 세션 상태다. 그룹/해제·재부모화는 시각 배치와 DOM 읽기 순서를 검증한다. 흐름 배치의 이동은 순서/정렬/간격 변경이고, absolute 요소만 좌표 이동이다. 리사이즈는 width/height/basis 등으로 기록하며 전체 텍스트를 transform scale로 눌러 맞추지 않는다.

정렬/분배는 같은 배치 문맥에서만 제공한다. 여러 부모·readonly·상충하는 자동 배치가 섞이면 적용 가능 부분만 몰래 바꾸지 말고 명령 전체를 거부하거나 명시적으로 대상을 다시 선택하게 한다.

## 반응형 계약

- 기본 프로필: mobile은 640px 미만, tablet은 640px 이상 1024px 미만, desktop은 1024px 이상. 검사 폭은 360/768/1280px이며 경계 639/640/1023/1024px도 시험한다.
- base는 공통 값이다. tablet과 mobile은 각각 base를 상속하고 서로 연쇄 상속하지 않는다. 기존 v2의 의미를 보존한다.
- 값 미지정은 상속, 0/false/빈 alt는 명시 값, reset은 해당 override 제거다. 전체 스타일 초기화와 개별 속성 초기화를 구분한다.
- 선택한 폭에서 수정하면 그 폭의 override를 편집한다. 공통값 편집으로 전환하려면 명시적인 UI를 사용한다. 현재 적용값·원천·다른 폭 영향이 보여야 한다.
- 구조 트리는 공통이다. 화면별 별도 노드 복제 대신 레이아웃·표시 재정의를 사용한다. 시각 순서와 키보드/스크린리더 순서가 불일치하는 변경은 경고하고 수용 시험에 포함한다.
- 데스크톱 브라우저에서 세 폭 모두 편집한다. 휴대전화의 터치 전용 전체 편집 UX는 별도 후속 범위이며 모바일 출력/반응형 편집 요구와 혼동하지 않는다.

## 조작과 이력

Puck 구조 DnD, Moveable 핸들, Selecto 영역 선택, Tiptap 텍스트 범위가 입력 소유권을 명시한다. 텍스트 입력 중 Delete·화살표·Cmd/Ctrl+A는 글자 편집을 우선하며 노드 삭제/전체 선택으로 전파하지 않는다.

사용자 동작은 시작 문서/session/revision/노드 ID/readonly를 포함한 명령으로 실행한다. gesture 중 표시용 초안과 확정 문서 상태를 구분한다. 종료 시 한 번 확정하고 Esc·포커스 상실·문서 전환·권한 변경·실패 시 초안을 취소한다. 모든 write는 최신 문맥을 다시 확인한다.

Puck history를 재사용하되 PB 명령의 한 트랜잭션과 대응시킨다. 다중 변경·그룹·복사/붙여넣기·preset 적용은 한 Undo 항목이다. 선택·팬·줌은 이력을 늘리지 않는다. 별도 Undo 스택을 추가해 입력 경합을 숨기지 않는다. 기존 Puck history 빌드 보정은 vendor 버전/지문 검사를 유지하고 엔진 업그레이드 때 함께 재검증한다.

IP1은 React 19, 고정 Puck, same-origin iframe, portal, 50/100/200% 줌과 문서 스크롤에서 이를 증명한다. 라이브러리 데모 성공을 제품 결합 성공으로 보고하지 않는다.

## 독립 구조와 G7 연결

| 책임 | 소유와 금지 |
|---|---|
| 문서 도메인 | 버전·typed 디자인·트리·순수 검증/명령; G7/Laravel/Puck/React/DOM/I/O 금지 |
| 편집 사용 사례 | 세션·명령 원자성·Undo 연동·저장/발행 흐름; 도메인과 포트에만 의존 |
| 편집 UI | 레이어·Inspector·상태/오류·캔버스 조립; 문서 규칙/저장 통신을 복제하지 않음 |
| EditorAdapter | Puck codec/dispatch/history, 입력 우선순위; vendor 객체를 도메인에 유출하지 않음 |
| InteractionAdapter | Moveable/Selecto 좌표·이벤트를 typed 명령으로 변환; DOM 결과를 원본으로 저장하지 않음 |
| 서비스 포트 | 문서 저장·자산·route catalog·동적 데이터·권한·clock/ID; 실제 구현을 주입 |
| G7 Adapter | 공개 인증·미디어·route·데이터·모듈 연결; core 수정이나 native editor API를 요구하지 않음 |
| 렌더/컴파일 | 공통 의미 명세와 fixture를 쓰는 React 편집 renderer와 PHP 정적 compiler; 결과 일치 검증 |

독립 검증 환경은 메모리/테스트 저장·자산·권한 포트를 사용한다. 이것이 실제 G7의 권한/동시 저장 시험을 대신하지 않는다. 런타임에 Node 서버·Rust daemon·Redis를 추가하지 않으며 고객 서버에서 빌드하지 않는다.

G7 JSON UI 출력은 선택형 생성 target이고 G7 원본 가져오기/양방향 동기화가 아니다. G7 테마 shell은 외부 소유라는 표시와 실제 공개 미리보기로 구분한다. PB builder shell에서는 PB Header/Footer를 상세 편집하며 인증 등의 동작은 고정 runtime adapter가 유지한다.

## 호환과 실패 복구

1. 기존 문서는 기존 편집/출력으로 계속 연다. 상세 편집 전환을 사용자가 명시적으로 선택할 때만 변환 후보를 만든다.
2. 변환 후보는 원본 revision·schema/compiler 버전·자산/주소·알 수 없는 필드·내장 블록별 매핑을 검사한다. 지원 불가가 있으면 원본을 변경하지 않는다.
3. 변환은 초안에서 수행하고 Undo 또는 보존 revision 복원 경로를 제공한다. 변환 성공이 자동 발행을 뜻하지 않는다.
4. 발행은 서버 검증·컴파일 성공 뒤 active publication을 원자적으로 교체한다. Header/Footer 세트는 둘 다 준비된 경우에만 전환한다.
5. 저장 실패·409 충돌·자산 실패·선택 capability 부재·호스트 업그레이드 실패가 문서나 마지막 정상 발행본을 지우지 않도록 검증한다.

## 제품 합격 기준

첫 통합 시나리오는 빈 페이지에 이미지·제목·본문·버튼을 넣고, 중첩·정밀 크기/간격·순서·다중 선택·모바일 값을 변경한 뒤 Undo/Redo·저장·재열기·미리보기·발행을 비교하는 것이다. 이는 최소 경로이며 전체 카탈로그 합격이 아니다.

최종 합격에는 다음이 필요하다.

- 위 SPEC-01~SPEC-16별 소스·단위·브라우저 증거와 내장 block/preset별 편집 capability 표. 미구현을 skip하거나 대표 사례로 대체하지 않는다.
- 동일 브라우저·font/image 준비 조건에서 편집/preview/public의 노드 순서·줄바꿈·computed style·bounding box 비교. 기본 치수 오차는 1 CSS px 이하; 예외는 명시된 renderer 원인과 fixture로 제한한다.
- 이미지 없음·긴 한글·빈 문구·중첩·회전/겹침·스크롤·3폭·명암 모드·키보드·IME·에러/readonly·동시 저장을 포함한다.
- 확정한 한도 내 100/500노드 fixture의 로딩·명령·포인터 성능을 동일 환경에서 기록한다. IP1/IP2에서 한도와 지연 예산을 고정하고 후속 기능을 넣어도 예산을 임의 완화하지 않는다.
- G7 없는 독립 검증과 지원 G7/테마 조합의 연결 시험을 모두 통과한다. 배포는 별도 승인된 버전·복구·실환경 증거로 판정한다.

## 라이브러리 근거

2026-10-12 확인. 다음은 부품의 제공 기능 근거이며 현재 PB 결합 성공의 증거가 아니다.

- [Puck Slot](https://puckeditor.com/docs/api-reference/fields/slot): 중첩 구성과 Flex/Grid 배치의 출발점.
- [Puck Viewports](https://puckeditor.com/docs/integrating-puck/viewports): iframe 작업면과 확대/축소 연결 경로.
- [Moveable](https://github.com/daybrush/moveable): 리사이즈·스냅·그룹 조작 후보.
- [Selecto](https://github.com/daybrush/selecto): 영역/추가 선택 후보.

추가 패키지의 정확 버전·라이선스 고지·브라우저 지원·번들 크기·취약점·유지보수 상태는 IP1의 도입 기록으로 확정한다. 유료 Cloud/Pro와 Figma SDK는 필수 의존성이 아니다.
