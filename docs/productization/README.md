기준일: 2026-08-31. 시작 SHA: `8b75d3a654638bfeb932985f67f8106ef05c8c42`.

사용자는 G7 참고 설계를 포함한 8차 개선 계획을 1차부터 추진하고 차수별로 자동 커밋하도록 지시했습니다. 계획의 실행 단위는 유지하고, 차수별 결과를 섞지 않습니다. 소스 제출·통합·제품 합격·운영 배포는 서로 다른 상태입니다.

현재 기준 `f9ed5a4`에는 **2-A~2-D 증거 분리·140개 의존성·영향별 갱신·상태 fixture와 태블릿 패널 수정**이 통합됐습니다. 이번 2-E1은 개발 기술 검증과 과거 통합 승인을 분리하며 제출/통합 SHA는 Git/coordination 기록으로 확인합니다. 사용자의 계속 진행 지시에 따라 동일 진행 승인을 다시 요청하지 않습니다. 미통합 공개 CSS 후보의 실제 브라우저 비교에서 내부 요소 높이 69건이 달라 2-E2 화면 수정·썸네일 재검증을 남깁니다. 560개 신규 심사/검증은 pending이고 릴리스는 계속 차단합니다. [2-E1 실행 기록](phase-2-development-gates.md)에 개발 검사·제품 승인·후속 수락 조건을 구분합니다. 2차 전체 완료나 3차 중첩 구현 완료를 선언하지 않습니다.

## 차수 진행과 커밋

3-A2는 `ec02b08` 제출 후 `3216093`에 통합했고 TS 383개와 frontend production gate를 통과했습니다. [3-A3 실사용 회귀 및 마지막 승인 목록](phase-3-seo.md)에 저장 요청·서버값·재진입·preview·public의 구분, 기존 서버 SEO 보존 로직에 대한 분석 정정, 전체 차수별 미완료 범위를 정리합니다. 프런트 누락을 실제 DB 유실로 보고하지 않습니다.

3-A1은 `ed8d1a0`에 통합했습니다. 후속 [3-A2](phase-3-adapter.md)는 문서 왕복 변환을 별도 모듈로 분리하고 파일별 coverage와 정책/fixture 증거 추적을 연결합니다. 분리 과정에서 기존 SEO가 왕복 시 유실되는 결함을 실패 시험으로 확인해 수정했으며, 실제 편집/저장/발행 검증은 별도 실행으로 구분합니다.

3-B는 [최소 중첩 실행 기록](phase-3-minimum-nesting.md)에 따라 Puck slot과 canonical v2, PHP 재귀 compiler를 `Section → 2열 Columns → Heading/RichText` 한 경로로 연결합니다. 일반 문서 생성은 계속 v1이고 Layout Columns를 root 라이브러리에 직접 노출하지 않습니다. 작업트리의 fixture·TS/PHP 단위 검사는 통과했으며 DB/G7 실제 브라우저 결과는 제출·통합 뒤 full profile 결과로 확정합니다. 3-C 경계·복구, 4차 구조 UI, 5차 사용자 Section, 사람 심사와 배포는 완료로 표시하지 않습니다.

3-C는 [경계·복구 실행 기록](phase-3-boundaries.md)에 따라 Puck 변환·공통 TS/PHP 한도·DB 저장 원자성·v1 revision 메타데이터·마지막 정상 발행본을 한 부정 시험 흐름으로 닫습니다. Stack과 전체 구조 UI를 추가하지 않고, 아직 미지원인 구조의 compile 실패도 publication pointer를 바꾸지 않는지 판정합니다. 4차 구조 조작·반응형·전환 UI는 별도 차수입니다.

4-A는 [구조 조작 실행 기록](phase-4-structure.md)에 따라 Puck native slot 위에 Stack·1/2/3열·제한된 기본 요소를 연결합니다. 내부 구조는 허용된 부모의 검사기에서만 추가하고, 열 축소는 콘텐츠 이동 확인·취소를 거치며 자식이 있는 구조 삭제도 별도 확인합니다. canonical/Puck/PHP 발행을 compiler 0.18.0으로 맞추되 반응형 상속·v1→v2 전환·저장/Undo 회귀는 4-B·4-C에서 닫습니다.

사용자의 남은 차수 연속 추진 지시에 따라 **3-A1의 순수 문서 트리·공통 구조 정책**을 독립 준비 배치로 진행합니다. [3-A1 실행 기록](phase-3-tree.md)에 TS/PHP 공통 fixture, 이동/복제/열 축소의 원본 보존과 실제 검증 범위를 기록합니다. 아직 기존 어댑터·API·발행에 연결하지 않았으며 2차 합격 또는 3차 기능 완료를 뜻하지 않습니다. 현재 공개 CSS 통합은 최신 썸네일 증거 140개와 기존 작업의 소유 범위가 맞지 않아 자동 취소됐습니다. 소유권/증거 조정, 사람 심사, 운영 배포처럼 필요한 승인은 마지막으로 모으고, 그 경계를 우회하지 않습니다.

1. 차수별 정확한 파일 범위와 검증 profile을 소유한 worktree에서 작업합니다.
2. 필수 검사 뒤 `make task-submit TASK=<id>`로 자동 커밋·제출합니다. 수동 stage/commit으로 우회하지 않습니다.
3. integration/runtime 소유자가 통합 게이트를 통과시킨 뒤 다음 구현 기준 SHA를 정합니다.
4. 합의된 기술 범위 안에서는 이번 추진 지시에 따라 순차 진행·자동 커밋합니다. 범위 확대·파괴적 이행·운영 배포·사람의 시각 승인은 별도 권한/증거 경계를 유지합니다.
5. 기존 활성 작업의 dirty 파일·lease를 가져오거나 해제하지 않습니다. 차수의 필수 선행 조건이 충족되지 않으면 제출된 산출물과 남은 조건을 보고하며 다음 차수 완료로 건너뛰지 않습니다.

## 1차 종료 조건

| 조건 | 증거 |
|---|---|
| 정책·호환·제외 범위가 구체적이고 서로 일치 | 위 계약과 요구사항 ID |
| 현행 모든 항목이 정확히 한 처리 배치에 배정 | inventory ID 대조·누락/중복 0 |
| 기존 검증 기반과 실제 실패/미실행이 구분 | phase-1-evidence |
| 기존 편집 수정 통합 후 사용자 동작 재확인 | 통합 SHA와 실제 포인터·저장·공개 결과 |

문서 제출만 끝난 상태를 1차 제품 합격으로 표현하지 않습니다. 한편 사람 확인을 기다리기 위해 이미 작성·검증한 1차 문서 커밋을 보류하지 않습니다.

1차의 기준 수립·현행 동작 확인을 끝냈다는 뜻이지 미통합 CSS, 새 중첩 기능, 전체 카탈로그의 품질 합격이나 릴리스 검증 완료라는 뜻은 아닙니다. 이 범위 안의 후속 차수마다 같은 진행 승인을 반복 요청하지 않습니다.
